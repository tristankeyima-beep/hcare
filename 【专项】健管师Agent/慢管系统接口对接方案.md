# 慢管系统接口对接方案

## 1. 目标与结论

健管师 Agent 需要从慢管系统读取患者档案等业务数据。

已完成 Demo 环境联调：使用健管师账号登录取得用户 Token 后，能够成功调用患者基础档案查询接口。机器账号的 `client_credentials` Token 可以成功签发，但当前未获得该档案接口的操作权限，因此 Demo 阶段采用“健管师登录 Token”方案。

> 正式生产接入仍建议由慢管平台为机器账号授予最小必要接口权限，避免以用户会话 Token 作为长期系统间凭证。

## 2. 公共约定

| 项目 | 约定 |
| --- | --- |
| API 基地址 | `https://hcare-api.gtmahmo.com` |
| 租户 Header | `sys-tenant-id: {TENANT_ID}` |
| 机构 Header | `org-info-id: {ORG_INFO_ID}` |
| 业务鉴权 Header | `Authorization: Bearer {ACCESS_TOKEN}` |
| 业务请求 Content-Type | `application/json` |

`sys-tenant-id` 与 `org-info-id` 是业务接口必传 Header；健管师登录接口也依赖机构 Header，缺失时服务端返回“机构的请求未传递”。

除本方案第 3 节按 Demo 联调需要记录的参数外，账号、密码、Client Secret、Access Token、Refresh Token 均应通过服务端密钥管理或运行环境变量注入，禁止写入前端、小程序或日志。

### 4.7 患者列表查询

| 项目 | 内容 |
| --- | --- |
| 方法 | `POST` |
| 地址 | `https://hcare-api.gtmahmo.com/org-api/cdm/contract-patient/page` |
| 请求体 | `{"dmScaleMarkTypes":["1"],"pageSize":10,"pageNo":1}` |

接口也支持通过 `keyword` 按患者姓名或手机号搜索。示例：

```json
{"keyword":"饶真朴","pageSize":10,"pageNo":1}
```

```json

```

也支持按患者的主责健管师查询。`signOperatorOrgUserIds` 为健管师成员在慢管系统中的 ID，可过滤由指定健管师管理的患者：


请求体筛选字段说明：

| 字段 | 含义 | 枚举值 |

| `dmScaleMarkTypes` | 高血压分标 | `1` 红标，`2` 黄标，`3` 绿标 |
| `dmScaleLevelTypes` | 高血压分层 | `1` 高危层，`2` 中危层，`3` 低危层 |
| `htmScaleMarkTypes` | 糖尿病分标 | `1` 红标，`2` 黄标，`3` 绿标 |

## 5. 推荐的 Demo 调用链路

```text
健管师 Agent 后端
  │
  ├─ POST /org-api/auth/login
  │    携带机构和租户 Header，以及健管师测试账号密码
  │
  ├─ 从响应 data.accessToken 取得短期用户 Token
  │
  └─ 业务 API 请求
       Authorization: Bearer {accessToken}
       sys-tenant-id: {TENANT_ID}
       org-info-id: {ORG_INFO_ID}
```

登录 Token 的有效期以响应中的 `expiresTime` 为准。Token 过期或业务接口返回鉴权失败时，应重新登录一次并仅重试原请求一次，避免无限重试。

## 6. 健管师登录

### 请求

```http
POST /org-api/auth/login HTTP/1.1
Host: hcare-api.gtmahmo.com
Content-Type: application/json
sys-tenant-id: {TENANT_ID}
org-info-id: {ORG_INFO_ID}

{
  "orgUserLoginId": "{HEALTH_MANAGER_LOGIN_ID}",
  "password": "{HEALTH_MANAGER_PASSWORD}"
}
```

### 成功响应结构

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "accessToken": "{ACCESS_TOKEN}",
    "refreshToken": "{REFRESH_TOKEN}",
    "expiresTime": "{EXPIRES_TIME}",
    "orgUserId": "{ORG_USER_ID}"
  }
}
```

调用业务接口时取 `data.accessToken`，并拼为 `Authorization: Bearer {ACCESS_TOKEN}`。Token 和登录密码不得输出到日志或接口响应中。

## 8. 机器账号方案与权限现状

慢管平台也提供 OAuth 2.0 `client_credentials` 模式：

```http
POST /org-api/oauth2/token HTTP/1.1
Host: hcare-api.gtmahmo.com
Content-Type: application/x-www-form-urlencoded
sys-tenant-id: {TENANT_ID}
org-info-id: {ORG_INFO_ID}
Authorization: Basic {Base64(CLIENT_ID:CLIENT_SECRET)}

grant_type=client_credentials&redirect_uri={REDIRECT_URI}&state={STATE}
```

其中 `Base64(CLIENT_ID:CLIENT_SECRET)` 是编码而不是加密，仍必须通过 HTTPS 传输并仅保存在服务端。

该方式在当前 Demo 中的验证结果：

- Token 签发成功，响应 `expires_in` 为约 30 分钟。
- 调用患者基础档案接口时返回业务码 `403`，提示“没有该操作权限”。

因此，若切换到机器账号正式接入，需要慢管平台为对应 Client、租户和机构授予 `GET /org-api/cdm/patient-icpr/basic-archive` 及后续所需 API 的最小权限和数据范围。

## 9. 后端实现要求

1. 只能由后端调用慢管 API；前端只调用健管师 Agent 自身的后端接口。
2. 为登录 Token 建立内存或 Redis 缓存，缓存键至少区分租户、机构和健管师账号。
3. 请求失败时记录请求链路 ID、HTTP 状态、业务码和脱敏错误信息；禁止记录密码、Token 和患者完整档案。
4. 对 `401`、Token 过期或可确认的鉴权失败，仅执行一次“重新登录 + 原请求重试”。
5. 患者数据属于敏感健康信息：按最小范围查询、最短时间缓存，并落实访问审计与脱敏展示。
