# 健康管理小程序 C 端设计规范

本文档用于后续生成健康管理小程序 C 端 HTML 页面时参考，目标是保证页面在视觉气质、字号、间距、组件、文案表达和高保真交付标准上保持一致。

本规范不仅用于“写出页面”，也用于把 HTML 作为 UI 设计稿交付给前端。页面应尽量接近真实小程序首屏效果，而不是只展示结构和文案。

## 1. 产品气质

整体风格应体现：

- 可信：像正规医疗健康服务，不花哨、不营销化。
- 温和：避免强刺激色、大面积警示色，降低用户焦虑。
- 清晰：信息层级明确，用户一眼知道今天要做什么。
- 陪伴感：文案和视觉要像健康管家，而不是医院后台系统。
- 生活化：适合日常使用，不要过度专业、冰冷或复杂。

推荐关键词：

```text
可信医疗 / 温和陪伴 / 清晰行动 / 轻量生活化
```

避免：

```text
过度科技感、深色大屏风、营销活动页、后台管理系统感、过多渐变和强阴影
```

## 2. 色彩规范

最新 C 端配色以“低饱和青绿色健康感”为主：页面更安静、更克制，内容容器以白色为主，关键行动使用柔和青绿色，提醒色只在必要位置出现。整体应清透、稳定、生活化，避免强蓝医疗后台感和多色运营入口感。

```css
:root {
  --color-primary: #4fa99f;
  --color-primary-deep: #3b8f86;
  --color-primary-dark: #2f736d;
  --color-primary-soft: #edf7f5;
  --color-primary-pale: #f4fbf9;

  --color-success: #7bbf9a;
  --color-warning: #f1b36b;
  --color-danger: #e88484;

  --color-bg: #f7f9f8;
  --color-weak-bg: #f8fbfa;
  --color-card: #ffffff;
  --color-line: #e9efed;
  --color-line-strong: #dfe9e6;

  --color-text-main: #24313a;
  --color-text-secondary: #6f7b83;
  --color-text-muted: #9aa5ac;
  --color-white: #ffffff;
}
```

使用原则：

- 主色用于导航选中态、主要按钮、关键行动入口。
- 成功色用于已完成、稳定、正常状态。
- 橙色只用于轻提醒或待查看状态，不要大面积铺底。
- 错误色只用于风险、异常、失败状态。
- 背景以近白浅灰绿为主，可在顶部使用很淡的青绿色过渡。
- 卡片以白色为主，用浅边框承担层级，不要依赖大量阴影。
- 服务入口图标统一使用浅主色底，不再用多色渐变区分业务。
- 不要回到强蓝主导的医疗后台风格。

状态色使用规则：

| 状态 | 色彩用途 | 建议 |
| --- | --- | --- |
| 正常/稳定 | `#7BBF9A` | 只用于“平稳、已完成、状态良好” |
| 待查看/提醒 | `#F1B36B` | 用于轻提醒，不做大面积背景 |
| 异常/风险 | `#E88484` | 只用于异常指标，不出现在常规任务 |

## 3. 字体规范

小程序端字号要克制，建议控制在 6-7 个层级内。

```css
:root {
  --font-xs: 11px;       /* 标签、底部导航文字 */
  --font-sm: 12px;       /* 辅助说明、时间、描述 */
  --font-body: 15px;     /* 正文、普通按钮 */
  --font-md: 16px;       /* 重要正文、详情正文、消息标题 */
  --font-title: 17px;    /* 模块标题 */
  --font-card: 17px;     /* 卡片标题 */
  --font-main-card: 20px; /* 首页主卡标题 */
  --font-page: 24px;     /* 页面主标题 */
}
```

使用原则：

- 页面标题：`24px / 700`
- 主卡标题：`20px / 700`
- 模块标题：`17px / 600`
- 卡片标题：`16-17px / 600`
- 正文内容：`15px / 400-500`
- 辅助说明：`13px / 400`
- 详情页长正文、任务步骤、方案说明建议使用 `15-16px`，优先保证中老年患者可读性。
- 标签文字：`11-12px / 600`
- 除主卡标题外，不要随意出现 `19px`、`20px`、`22px`、`28px`、`32px` 等孤立字号。
- 中文行高建议 `1.35-1.6`，长段说明用 `1.6`。

## 4. 间距规范

推荐使用固定间距节奏，避免每个模块单独写随机数。

```css
:root {
  --space-page: 16px;     /* 页面左右边距 */
  --space-section: 20px;  /* 大模块之间距离 */
  --space-related: 14px;  /* 强相关模块之间距离 */
  --space-card: 16px;     /* 卡片内边距 */
  --space-gap: 10px;      /* 卡片/列表之间间距 */
}
```

使用原则：

- 页面左右边距：`16px`
- 页面顶部内容边距：`16-18px`
- 模块标题到内容：`10-12px`
- 模块之间：`20-22px`
- 卡片内边距：`12-16px`
- 列表项间距：`10-12px`
- 小卡片网格 gap：`8-10px`
- 底部导航与屏幕边缘：`12-16px`
- 所有可点击区域建议不小于 `44px × 44px`，视觉尺寸较小的图标按钮应扩大热区。
- 相邻点击目标之间建议至少保留 `8px` 间距，避免误触。

## 5. 圆角与阴影

C 端小程序需要柔和，但不要所有元素都巨大圆角。

```css
:root {
  --radius-xs: 8px;
  --radius-sm: 10px;
  --radius-md: 14px;
  --radius-lg: 18px;
  --radius-nav: 20px;

  --shadow-card: 0 4px 14px rgba(36, 49, 58, 0.04);
  --shadow-primary: 0 8px 22px rgba(62, 156, 146, 0.08);
}
```

使用原则：

- 小按钮、小标签：`10-12px`
- 图标容器、输入框：`12-14px`
- 普通卡片：`16-18px`
- 重点卡片：`18px`
- 底部 TabBar：`20px`
- 阴影要轻，只在主卡、浮层或底部导航上使用。
- 优先用 `1px solid #E9EFED` 建立层级。
- 不要使用过多玻璃拟态和装饰光晕，医疗健康产品要稳定、清楚。

## 6. 页面结构规范

首页推荐结构：

```text
状态栏
小程序顶部栏：品牌名 + 小程序胶囊菜单
顶部问候 + 今日状态一句话 + 今日状态环
今日行动卡
今日状态总览卡
核心服务快捷入口
服务团队留言
今日推荐
底部 TabBar
```

信息优先级：

1. 今日最重要的一条行动，并解释为什么要做
2. 今日状态总览，只呈现状态判断，不承载待办任务
3. 高频核心服务入口
4. 医生/健管师团队留言
5. 单条轻内容推荐

首页不建议同时放“科普视频”和“健康资讯”两个运营内容区。保留一个“今日推荐”即可。

顶部区域要求：

- 小程序设计稿应模拟真实微信小程序顶部环境，包括状态栏、小程序名称和右上角胶囊菜单。
- 顶部问候区可以放一个轻量状态环，用于表达“今日状态”，但不要做成复杂数据仪表盘。
- 顶部不要放搜索框、活动 banner 或营销入口，首页第一屏应服务于“今天要做什么”。

## 7. 通用页面类型规范

C 端不应只按首页规则生成页面。不同页面类型的信息密度、操作强度和解释深度不同，应按页面目的选择结构。

| 页面类型 | 主要目标 | 推荐结构 | 设计重点 | 避免 |
| --- | --- | --- | --- | --- |
| 首页 | 让患者知道今天状态和先做什么 | 顶部状态、今日行动、状态总览、核心入口、团队/推荐 | 首屏判断清晰，只突出一个主行动 | 功能宫格堆叠、多个主任务、营销 banner |
| 列表页 | 帮用户快速扫读和选择对象 | 页面标题、筛选/日期/分组、列表卡、空状态 | 扫读效率、分组清晰、操作直接 | 列表卡做成海报、重复 Tab、过多解释块 |
| 详情页 | 解释内容并承接一个主动作 | 标题区、核心信息、原因说明、执行/阅读内容、底部主按钮 | 信息层级、阅读舒适、主动作明确 | 多个并列主按钮、卡片套卡片、机制说明外露 |
| 表单/记录页 | 帮用户准确录入健康数据 | 标题、字段分组、输入项、辅助说明、提交反馈 | 输入效率、错误提示、默认值合理 | 一屏字段过多、只用 placeholder、错误只放顶部 |
| 空状态页 | 告诉用户当前没有内容和下一步 | 状态说明、温和原因、一个行动入口 | 不制造焦虑，给明确下一步 | 只写“暂无数据”、无操作出口 |

### 列表页原则

- 列表页第一屏应优先展示筛选/日期/分组和最重要的列表项。
- 同一层级不要出现两套功能相同的分组控件。例如分类卡已经可点击，就不要再放重复 Tab。
- 列表卡只展示决策所需信息：名称、状态/标签、必要说明、一个主动作。
- 对 C 端患者，列表页不解释复杂规则，规则放到详情页或帮助页。

### 详情页原则

- 详情页只保留一个主动作，底部固定主按钮时，页面中同一动作不重复出现。
- 「来源」信息只展示一次：若顶部已展示“来自用药指导”，内容区不再重复“来源方案”。
- 说明内容按“为什么要做 → 怎么做 → 现在做什么”的顺序组织。
- 内部策略不直接展示给患者，例如 AI/人工分流、算法置信度、系统生成逻辑等。

## 8. 首页卡片设计规范表

本节用于产品、前端、后端对齐首页卡片的展示规则、数据来源、字段优先级和缺省展示。接口名称为产品约定示例，可在技术评审时调整，但字段含义和展示规则应保持一致。

首页卡片总表：

| 卡片类型 | 卡片名称 | 主要作用 | 首页优先级 | 建议数量 | 是否固定出现在首页 | 典型内容 | 建议接口/数据模块 |
| --- | --- | ---: | ---: | ---: | ---: | --- | --- |
| B类 | 今日行动卡 | 告诉用户今天最重要的一件事，并结合当前状态说明原因 | 一级 | 1 | 是 | 饮食确认、运动确认、用药确认、原因说明、相关提醒 | `home.primaryAction` |
| A类 | 状态总览卡 | 呈现用户今日整体状态，建立首页主判断 | 一级 | 1 | 是 | 今日状态、关键指标、状态详情入口 | `home.summary` |
| C类 | 相关提醒行 | 承接与今日行动有关的次级提醒 | 一级附属 | 1 组，1-2 条 | 随今日行动展示 | 注射提醒、复诊提醒 | `home.primaryAction.relatedReminders` |
| D类 | 服务快捷入口 | 提供核心服务快捷入口 | 二级 | 1 组，4 个 | 是 | 问医生、今日记录、续方购药、健康计划 | `home.services` |
| E1类 | 服务团队卡 | 建立信任感与陪伴感 | 三级 | 1 | 建议保留 | 医生/健管师、留言摘要、咨询入口 | `home.careTeam` |
| E2类 | 内容推荐卡 | 作为轻量内容补充与延展阅读 | 三级 | 1 | 可选 | 节气饮食、科普文章、健康小贴士 | `home.recommendation` |
| T类 | 顶部轻提醒胶囊 | 仅用于异常、风险或系统级轻提醒 | 顶部辅助 | 0-1 | 可选 | 数据未同步、医生有新留言 | `home.topNotice` |

字段与展示规则：

| 卡片类型 | 必要字段 | 可选字段 | 展示规则 | 缺省/异常规则 |
| --- | --- | --- | --- | --- |
| B类 今日行动卡 | `actionId`、`statusLabel`、`title`、`description`、`reasonTitle`、`reasonText`、`ctaText`、`targetUrl` | `estimateMinutes`、`expireAt`、`category`、`statusBasis`、`relatedReminders[]` | 首页只展示 1 条最高优先级行动；必须说明“为什么现在要做”；原因说明要引用当前状态；相关提醒放在行动卡内，不单独占一个首页模块 | 今日无行动时展示温和空态，如“今天暂无必须处理事项”，不要制造焦虑 |
| A类 状态总览卡 | `score`、`statusText`、`summaryText`、`metrics[]`、`detailAction` | `updatedAt`、`scoreConfidence` | `score` 用于状态环，`metrics` 最多 3 个；只展示状态判断，不展示待办数量、复诊安排等任务信息 | 无评分时隐藏数字状态环，改用 `statusText`；关键指标缺失时不展示空指标 |
| C类 相关提醒行 | `items[]` | `item.iconType`、`item.timeText`、`item.status`、`item.targetUrl` | 最多展示 2 条；只展示与今日行动有关的提醒；放在今日行动卡内部 | 无相关提醒时隐藏，不占位 |
| T类 顶部轻提醒胶囊 | `message`、`badgeText`、`targetUrl` | `priority`、`iconType` | 只用于非重复的轻提醒，不得重复今日行动卡内容；文案不超过 20 个中文字符 | 无高优先级提醒时隐藏，不占位 |
| D类 服务快捷入口 | `serviceKey`、`title`、`iconType`、`targetUrl` | `statusText`、`badgeText` | 固定 4 个入口，一行展示；只展示图标和短标题，不展示长说明文案 | 某服务不可用时保留入口但状态显示“暂不可用”，点击进入说明页或置灰由产品确认 |
| E1类 服务团队卡 | `members[]`、`teamTitle`、`note`、`action` | `member.avatar`、`member.role`、`onlineStatus` | 最多展示 2 个头像或角色标识；留言摘要不超过 40 个中文字符；只保留 1 个沟通入口 | 无团队信息时可隐藏姓名，保留“服务团队留言”与通用说明 |
| E2类 内容推荐卡 | `contentId`、`title`、`summary`、`targetUrl` | `tagText`、`readTimeText`、`coverImage`、`illustrationType` | 首页只放 1 条；标题不超过 18 个中文字符；摘要不超过 34 个中文字符；不要同时出现多个运营内容区 | 无推荐内容时隐藏，不影响首页主流程 |

评分展示规则：

| 分值区间 | 状态文案 | 展示色 | 首页表达方式 | 注意事项 |
| --- | --- | --- | --- | --- |
| `85-100` | 状态很好 | 成功色/主色 | 可展示数字评分和状态环 | 不使用夸张表述，如“完美”“非常健康” |
| `70-84` | 状态平稳 | 主色 | 可展示数字评分和状态环 | 适合首页默认状态表达 |
| `55-69` | 建议关注 | 轻提醒色 | 可展示评分，但说明文案要温和 | 不使用“异常”“危险”等强刺激词 |
| `0-54` | 需要关注 | 谨慎使用危险色 | 数字可展示，但红色面积要小 | 必须给出明确下一步动作，如“查看团队留言” |
| 无分值 | 今日状态待更新 | 中性灰 | 不展示数字，展示状态文案 | 不能用 `0` 代替缺失分值 |

评分字段约定：

- `score` 仅用于健康管理状态提示，不作为诊断结论。
- `score` 应由后端或算法服务计算，前端只负责展示，不在前端临时拼算法。
- 当 `scoreConfidence` 低于约定阈值，或 `updatedAt` 不是当天数据时，不建议展示具体数字，只展示 `statusText`。
- 评分文案应始终包含下一步行动建议，避免只给用户一个分数。

首页聚合接口建议：

```text
GET /api/c/home
```

建议首页使用一个聚合接口返回首屏所需数据，减少多个卡片分别加载造成的闪烁。返回结构建议：

```json
{
  "primaryAction": {},
  "summary": {},
  "reminders": [],
  "services": [],
  "careTeam": {},
  "recommendation": {},
  "topNotice": {}
}
```

接口展示约定：

- 前端按卡片类型读取数据，不按接口返回顺序决定首页排序。
- 卡片排序由产品规范固定，后端只提供数据内容和优先级字段。
- 每类卡片都需要支持“无数据但页面正常”的展示方案。
- 涉及团队留言、用药提醒、复诊安排等内容时，后端应返回明确的 `targetUrl` 或业务跳转参数，避免前端硬编码跳转。
- 所有时间字段建议后端同时返回原始时间和展示文案，例如 `time` 与 `timeText`，首页优先展示 `timeText`。

## 9. 通用卡片视觉规范

普通卡片：

```css
.card {
  background: #fff;
  border: 1px solid #e9efed;
  border-radius: 18px;
  padding: 16px;
  box-shadow: 0 4px 14px rgba(36, 49, 58, 0.04);
}
```

重点卡片：

```css
.card-primary {
  color: #24313a;
  border-radius: 18px;
  padding: 18px;
  background: #fff;
  border: 1px solid #e9efed;
  box-shadow: 0 8px 22px rgba(62, 156, 146, 0.08);
}
```

使用原则：

- 不要卡片套卡片。
- 每张卡片只表达一个明确主题。
- 卡片标题、正文、状态标签要层级清楚。
- 重点卡片最多使用一条很淡的主色顶边或侧边，不要整块高饱和渐变。
- 列表卡片不要做得像海报，重点是扫读效率。
- 首页状态总览卡可以包含 3 个以内的摘要指标，如“血糖趋势 / 晚餐后 / 记录完整度”，用于增强真实产品感。
- 摘要指标应使用浅底小容器，不要用强色块或大数字抢走主卡标题。

## 10. 通用组件与状态规范

### 组件类型

| 组件 | 用途 | 结构建议 | 注意事项 |
| --- | --- | --- | --- |
| 列表卡 | 列表中承载单个任务/方案/记录 | 图标或缩略图、标题、标签、摘要、主动作 | 不做复杂装饰，主动作最多一个 |
| 详情说明卡 | 解释原因、依据、注意事项 | 标题、正文、关键字段 | 不要卡片套卡片，字段不重复 |
| 轻提醒条 | 提示未完成、待查看、授权等轻量事项 | 一句说明 + 一个动作 | 必须有下一步，不做纯提醒 |
| 底部操作区 | 页面主动作 | 一个主按钮，必要时一个弱次动作 | 避免两个同权重按钮并列 |
| 图片预览组 | 展示操作图、说明图、二维码 | 同尺寸横向滑动预览 | 无图则隐藏，不占位 |

### 交互状态

| 状态 | 展示要求 | 示例 |
| --- | --- | --- |
| 默认 | 信息完整、主动作清晰 | 去查看、去记录 |
| 按下 | 轻微压暗或状态层反馈 | 按钮按下反馈 |
| 加载中 | 主按钮禁用并显示加载反馈 | 提交中、保存中 |
| 禁用 | 降低对比度，说明不可用原因 | 未来任务暂不可完成 |
| 已完成 | 使用成功色或中性完成态，不大面积铺色 | 已完成、查看记录 |
| 未完成 | 中性提示，不使用惩罚文案 | 今日之前有 2 项未完成任务 |
| 图片失败 | 保留尺寸，提供重试或占位说明 | 图片加载失败，点击重试 |
| 空状态 | 温和说明 + 一个行动入口 | 今天暂无需要处理的任务 |

## 11. 今日行动规范

首页不要展示多个并列主任务，应突出“今天先做这一项”。任务能力可以保留，但表达要从任务中心转为陪伴式行动。

状态表达建议：

```text
今日行动：主色轻强调
现在可做：主色文字
已为您准备：中性状态
稍后确认：弱提醒
已过期：谨慎使用危险色
```

首页行动内容结构：

```text
状态标签
行动标题
温和说明
查看入口
1-2 条弱提示
```

示例：

```html
<article class="today-card">
  <div class="today-icon">
    <!-- 线性图标：calendar-check -->
  </div>
  <div>
    <small>现在可做</small>
    <h3>晚餐前确认饮食搭配</h3>
    <p>预计用时 2 分钟，确认后按这个搭配执行即可。</p>
    <a href="#">开始处理</a>
  </div>
</article>
```

避免：

```text
多个主行动
待完成
连续多个横向任务卡
大面积高亮任务卡
```

## 12. 底部导航规范

底部 TabBar 应稳定、清晰，不要过度装饰。

推荐栏目：

```text
首页 / 档案 / 咨询 / 我的
```

规范：

- 高度控制在 `64-76px`
- 图标区域 `28-32px`
- 文字 `11px`
- 选中态使用主色图标 + 主色文字 + 顶部短线
- 未选中态使用中性灰
- 激活态不建议整块渐变高亮。
- 不建议使用 emoji 或单字作为正式图标，可用 iconfont、小程序图标组件或线性 SVG。
- 底部 TabBar 应固定在页面底部视觉区域，页面内容需要预留底部安全距离，避免最后一张卡片被遮挡。

## 13. 图标规范

图标体系应使用统一线性风格：

- 线性图标，`2px` 描边。
- 圆角端点和圆角连接。
- 服务入口图标尺寸 `22-24px`。
- 底部导航图标尺寸 `20-22px`。
- 不同状态只改变颜色，不改变图标形态。
- 不建议使用 emoji 或单字图标作为正式视觉。

推荐图标方向：

| 功能 | 图标方向 |
| --- | --- |
| 问医生 | message-circle / stethoscope |
| 今日记录 | clipboard-list / edit-3 |
| 续方购药 | pill / medicine-box |
| 健康计划 | calendar-check |
| 首页 | home |
| 档案 | file-text |
| 咨询 | message-square |
| 我的 | user |

图标容器建议：

```css
.icon-box {
  width: 34px;
  height: 34px;
  border-radius: 12px;
  display: grid;
  place-items: center;
  color: #3b8f86;
  background: #edf7f5;
}
```

首页常用组件图标建议：

| 组件 | 图标方向 |
| --- | --- |
| 待办提醒 | bell / notification |
| 今日状态 | activity / circular-progress |
| 今日状态总览 | dot + card side bar |
| 今日行动 | book-open / calendar-check |
| 服务团队留言 | shield-check / users |
| 今日推荐 | article / book-open |

## 14. 按钮规范

按钮分为 4 类：

| 类型 | 用途 | 样式 |
| --- | --- | --- |
| Primary | 页面主动作 | 实色主色按钮 |
| Secondary | 次动作 | 浅主色底 + 主色字 |
| Tertiary | 轻动作 | 纯文字链接 |
| Navigation | 导航入口 | 图标 + 文案 |

使用原则：

- 每个主卡片最多保留一个 Primary 按钮。
- 次动作优先用 Tertiary 文字链接，避免多个胶囊按钮并列。
- 按钮字重建议 `600`，不要全部使用 `700`。
- 主按钮视觉高度建议 `44-48px`；小胶囊按钮视觉高度可为 `32-36px`，但点击热区仍需扩展到 `44px`。
- 同一页面只保留一个最强主动作。若存在“问问健管师”和“我已确认”，通常“我已确认”为底部主动作，“问问健管师”为内容区辅助动作。

## 15. 内容文案规范

健康管理场景文案要减少焦虑，强调陪伴式行动。

推荐：

```text
开始处理
已为您整理
现在可做
今日行动
状态平稳
待办提醒已为您整理好
今天先做这一项就好
```

谨慎使用：

```text
异常
严重
危险
高风险
必须
立即
逾期
漏做
补记
失败
未达标
```

除非确实是医学风险提示，否则不要用强刺激词。

文案结构建议：

```text
发生了什么 + 用户下一步可以做什么
```

例如：

```text
待办提醒已为您整理好
今天的饮食和用药安排已为您整理好，先完成晚餐前确认即可
```

文案替换建议：

```text
优先处理 -> 今日行动
待完成 -> 现在可做
系统已同步 -> 已为您整理
已生成 -> 已准备好
查看复诊计划 -> 看看本周复诊安排
逾期任务 -> 今日之前未完成任务
去补记 -> 去查看
漏做记录 -> 未完成记录
```

## 16. 健康任务页面专项规范

健康任务页是 C 端从“查看信息”走向“执行健康管理”的核心页面。设计重点是让患者知道今天做什么、为什么做、怎么做，而不是制造任务压力。

### 任务列表页

| 模块 | 推荐展示 | 设计要求 |
| --- | --- | --- |
| 日期切换 | 当前日期 + 前后切换 + 短日期条 | 支持看过去和未来任务；默认停留今天 |
| 今日之前未完成提示 | 今日之前有 N 项未完成任务 + 去查看 | 中性表达，不使用逾期、漏做、补记 |
| 任务分类 | 优先处理 / 轻松完成 / 需准备 | 分类卡本身可点击，不再重复放 Tab |
| 任务卡 | 图标、任务名、必要标签、主动作 | 标签只保留有用信息，如含图示、二维码、约1分钟 |

任务分类建议：

| 分类 | 定义 | 示例 |
| --- | --- | --- |
| 优先处理 | 与用药、异常指标、时效性强的任务相关 | 胰岛素剂量确认、异常指标复测 |
| 轻松完成 | 操作简单、耗时短、适合快速处理 | 血糖记录、步行打卡 |
| 需准备 | 需要材料、环境或外部配合 | 报告上传、复诊资料、扫码入群 |

### 任务详情页

| 模块 | 推荐展示 | 设计要求 |
| --- | --- | --- |
| 任务头部 | 任务图标、名称、标签、来源 | 来源只展示一次 |
| 为什么要做 | 原因说明、关联指标 | 解释价值，不堆医学术语 |
| 怎么完成 | 图片/二维码、步骤、问问健管师 | 图片和步骤在同一区域 |
| 底部主动作 | 我已确认 / 完成 / 提交 | 保持单一主按钮 |

详情页顺序建议：

```text
任务标题
为什么要做
怎么完成（图片/二维码 + 步骤 + 问问健管师）
底部主动作
```

咨询入口：

```text
问问健管师
```

- C 端不展示“AI 解读”“转人工”等内部机制说明。
- 若内部有 AI/人工分流，由系统策略处理，不在患者端显性表达。

## 17. 图片与二维码规范

健康任务和干预方案中可能出现操作图、药械图、任务说明图、微信群二维码等，图片是执行依据，不是装饰。

| 场景 | 展示规则 |
| --- | --- |
| 任务含操作图 | 在“怎么完成”区域展示 |
| 多张图片 | 使用同尺寸横向滑动预览 |
| 二维码 | 作为同尺寸预览项展示 |
| 无图片 | 隐藏图片区域，不占位 |
| 图片加载失败 | 保留尺寸，显示失败态和重试 |
| 点击图片 | 打开预览大图 |

图片组件建议：

- 预览图保持统一比例，建议 `1:1` 或 `4:3`，同一组内不要混用比例。
- 图片标题尽量短，例如“旋钮位置”“剂量刻度”“注意事项”。
- 二维码不要在列表页大面积展示，列表页只提示“二维码”标签，详情页再展示。
- 涉及用药、注射、器械操作的图片，不用夸张装饰和营销插画，应保持清楚、可识别。

## 18. 可访问性与适老化规范

C 端健康管理用户可能包含中老年患者，界面应优先保证可读、可点、可理解。

| 项目 | 要求 |
| --- | --- |
| 字号 | 正文默认不低于 `15px`，长说明和步骤可用 `15-16px` |
| 对比度 | 正文与背景对比要清晰，避免浅灰字大段展示 |
| 点击热区 | 不小于 `44px × 44px` |
| 文案 | 短句优先，少用系统术语和医学缩写 |
| 图片 | 可点击放大，重要图片不裁切关键区域 |
| 错误反馈 | 告诉用户下一步怎么做，不只提示失败 |
| 动效 | 微动效即可，避免大幅度动画和频繁闪烁 |

## 19. 高保真 HTML 交付规范

当 HTML 作为 UI 设计稿交付时，需要满足以下要求：

- 使用一个明确的手机画布，建议宽度按 `390-430px` 设计，兼容 `360px` 小屏。
- 页面应模拟真实小程序环境：状态栏、小程序顶部栏、右上角胶囊菜单、底部 TabBar。
- 组件不能只靠文字说明，应包含真实的状态标签、图标、按钮、列表项、时间和轻量数据。
- 图标应统一为线性 SVG 或同一套 iconfont，不使用 emoji、单字或风格混杂的图形。
- 所有卡片、按钮、标签、图标容器都应有稳定尺寸，避免文字变化导致布局跳动。
- 页面不放占位灰块，推荐内容缩略图可以用简单抽象插画，但要和健康饮食、记录、服务场景相关。
- 主色只用于关键行动和选中态，辅助信息使用中性灰，不用大面积渐变制造高级感。
- 设计稿应能直接打开预览，不依赖复杂工程环境；如需拆分文件，应保证路径清晰。

验收检查：

- 首屏能一眼看到“今日状态”和“今天最重要的一条行动”。
- 页面在 `360px` 和 `430px` 宽度下文字不溢出、不重叠。
- 底部导航不遮挡最后一屏内容。
- 同类组件的字号、圆角、图标尺寸和内边距一致。
- 没有营销页感、后台系统感、强科技感或过度装饰。

