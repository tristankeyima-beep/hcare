# C端改版迭代节奏

> 本文不绑定具体版本号，而是记录 C 端改版应掌握的迭代节奏。后续版本可以按资源、客户交付和 AI 能力成熟度切分，但产品方向应保持一致。

## 总体目标

C 端改版要围绕慢管产品核心展开：

```text
健康档案/随访/指标/饮食运动记录
→ AI 生成成果物
→ AI 生成 TodoList
→ 患者执行
→ 新数据回流
```

C 端本轮主要做三件事：

1. 增加干预方案在 C 端的展示，展示各个方案，并在首页展示一个“近况分析”。
2. 增加 C 端的待办任务模块。
3. 增加 AI 健管师，使其可以向患者解读方案、给出任务完成指导。

这三件事的顺序很重要：先让患者看懂“自己现在有什么方案和近况”，再让患者知道“今天要做什么”，最后用 AI 帮患者理解“为什么做、怎么做”。

## 迭代节奏一：方案展示与近况分析

### 核心目标

先把管理端交付给患者的内容，在 C 端以患者能理解的方式展示出来。

这里的重点不是简单同步管理端页面，而是把“干预方案”转译成 C 端的健康管理视图，让患者知道：

1. 当前有哪些生效中的方案。
2. 每个方案分别管什么。
3. 最近自己的状态怎么样。
4. 这些方案和自己的近况有什么关系。

### 主要范围

1. C 端增加干预方案展示。
2. 支持展示多个方案，例如饮食方案、运动方案、监测方案、随访计划、用药指导、健康周报等。
3. 首页增加“近况分析”模块。
4. 近况分析基于健康档案、指标记录、饮食运动记录、随访记录和当前生效方案做摘要。
5. 如果没有 AI 能力，近况分析可以先做成规则化/配置化摘要。
6. 如果启用 AI 能力，近况分析可由 AI 根据患者近期数据生成。

### 首页表达

首页不应堆叠所有方案，而应展示一个简洁判断：

```text
最近情况怎么样
当前最需要关注什么
建议先执行哪类方案或行动
```

方案详情页再承载完整内容。

### 产品判断

这是 C 端改版的第一步，因为没有方案展示和近况分析，患者就不知道后续待办和 AI 指导从哪里来。

## 迭代节奏二：C端待办任务模块

### 核心目标

把干预方案中的管理要求，落到患者每天可以执行的任务上。

待办不是普通任务列表，而是“方案到执行”的承接层。患者不应该只看到一堆方案文本，而应该看到今天要完成的具体动作。

### 主要范围

1. C 端增加待办任务入口。
2. 首页展示最重要的一条“今日待办”或“今日行动”。
3. 待办列表展示今日、未来、已完成、已过期等状态。
4. 待办详情展示任务名称、计划时间、任务说明、图片说明、关联指标、来源方案。
5. 支持任务完成动作，例如标记完成、跳转指标录入、跳转饮食运动记录。
6. 支持管理端配置生成的待办。
7. 后续支持 AI 根据方案和患者状态生成 TodoList，或对 TodoList 进行重排。

### 首页表达

首页只突出一条最重要的任务，不要把多个任务平铺成压力感很强的清单。

推荐表达：

```text
今日行动
晚餐前确认饮食搭配
为什么现在要做
开始处理
```

### 产品判断

待办是 C 端从“查看型小程序”变成“执行型小程序”的关键。如果没有待办，干预方案仍然停留在内容交付；有了待办，患者才有明确行动。

## 迭代节奏三：AI健管师解读与指导

### 核心目标

增加 AI 健管师，让患者能理解方案、理解待办，并获得完成任务的指导。

AI 健管师的价值不是多一个聊天入口，而是把管理端复杂的交付物转成患者能理解、能执行的话。

### 主要范围

1. C 端增加 AI 健管师入口。
2. 支持通用健康问题咨询。
3. 支持从方案详情进入 AI 解读，例如饮食方案解读、运动方案解读、用药指导解读、健康周报解读。
4. 支持从待办详情进入 AI 指导，例如“这个任务怎么完成”“运动前要注意什么”“这顿饭怎么搭配”。
5. AI 对话需要带入上下文，例如当前方案、任务说明、患者健康档案、近期指标和记录。
6. AI 输出要有边界提示，仅作为健康管理参考，不替代医生诊断。
7. AI 能力作为增值模块，需要和基础配置能力区分。

### 首页表达

AI 健管师可以作为独立入口，但更重要的是嵌入到方案和待办场景中：

```text
帮我解读这个方案
问问这个任务怎么做
为什么今天要完成这项
```

### 产品判断

AI 健管师要服务于“理解和执行”，不是独立聊天产品。它应该帮助患者降低理解成本，也帮助健管师减少重复解释成本。

## 三步之间的关系

这三步形成 C 端的核心链路：

```text
方案展示 + 近况分析
→ 待办任务
→ AI 解读和完成指导
```

对应到慢管大闭环中：

```text
健康档案和方案是输入
近况分析是解释
待办是执行动作
AI 健管师是理解和指导
患者完成后产生新数据回流
```

## 配置化与AI增强

每一步都要同时考虑两种形态：

### 基础配置版

适合不购买 AI 模块的客户。

能力包括：

1. 管理端配置方案，C 端规范化展示。
2. 管理端配置待办，C 端展示和提醒。
3. 固定规则生成近况摘要。
4. 固定内容推荐、图文和视频推荐。

### AI增强版

适合购买 AI 模块并承担 token 成本的客户。

能力包括：

1. AI 生成或改写近况分析。
2. AI 根据方案和患者状态生成 TodoList。
3. AI 对待办进行重排和优先级判断。
4. AI 解读方案。
5. AI 指导患者完成任务。

## 当前规划结论

C 端改版先不需要纠结具体落在哪个版本号，而要掌握节奏：

1. 先让患者看到方案和近况。
2. 再让患者有可执行的待办。
3. 再用 AI 帮患者理解方案和完成任务。

这个节奏能保证 C 端从“功能入口集合”逐步变成“患者执行和数据回流终端”。
