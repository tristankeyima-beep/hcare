# C端页面结构规划

> 目标：用患者视角组织页面，而不是照搬管理端功能。C 端主线是：看近况、看方案、做待办、问 AI、回流数据。

## 1. 页面地图

```text
C端小程序
├─ 首页
│  ├─ 近况分析详情
│  ├─ 今日待办详情
│  ├─ 全部待办
│  ├─ 生效方案列表
│  └─ 推荐内容详情
│
├─ 档案
│  ├─ 指标总览
│  │  ├─ 指标录入
│  │  └─ 指标趋势详情
│  ├─ 干预方案列表
│  │  └─ 干预方案详情
│  ├─ 饮食运动记录
│  │  ├─ 饮食记录
│  │  └─ 运动记录
│  ├─ 随访记录
│  │  └─ 随访详情
│  ├─ 用药/取药记录
│  └─ 报告检查
│
├─ 咨询
│  ├─ AI健管师
│  ├─ 方案解读

│  └─ 服务团队沟通

   ├─ 我的签约
   ├─ 签约详情

   └─ 账号设置
```

## 2. 一级页面定位

| 一级页面 | 页面定位 | 用户来这里做什么 | 本次改版重点 |
| --- | --- | --- | --- |
| 首页 | 今日健康管理入口 | 看近况、看今日行动、进入方案/待办/咨询 | 近况分析、今日待办、生效方案摘要 |
| 档案 | 数据和方案沉淀 | 查看指标、记录数据、查看方案和随访 | 健康档案、干预方案展示 |
| 咨询 | AI 和服务团队连接 | 问 AI、问团队、解读方案和任务 | AI 健管师、方案解读、待办指导 |
| 我的 | 账户和服务身份 | 看签约、认证、设置、授权 | 签约信息、消息授权、设备管理 |

## 3. 核心页面拆解

### 首页

首页只解决三个问题：

```text
我最近怎么样？
我今天先做什么？
有问题找谁？
```

建议模块顺序：

| 模块 | 作用 | 跳转 |
| --- | --- | --- |
| 顶部服务身份 | 展示患者身份、签约团队或服务状态 | 我的签约 / 服务团队 |
| 近况分析 | 汇总近期指标、方案执行、待办完成情况 | 近况分析详情 / AI 解读 |
| 今日待办 | 展示最重要的一条行动 | 待办详情 |
| 生效方案摘要 | 告诉患者当前有哪些方案在执行 | 干预方案列表 |
| 服务团队留言 | 建立真人服务连接 | 服务团队沟通 |
| 今日推荐 | 单条图文/视频推荐 | 推荐详情 |

### 档案

档案是数据底座，不做成杂乱功能宫格。建议按“数据记录”和“管理成果”分组。

| 分组 | 页面 | 说明 |
| --- | --- | --- |
| 数据记录 | 指标总览、指标录入、指标趋势详情 | 血糖、血压、体重、BMI、心率等 |
| 数据记录 | 饮食运动记录 | 饮食打卡、运动打卡、热量和营养分析 |
| 数据记录 | 随访记录 | PC/管理端同步给患者查看 |
| 管理成果 | 干预方案列表、干预方案详情 | 饮食、运动、监测、随访、用药、周报 |
| 管理成果 | 用药/取药记录 | 用药指导、取药记录、用药注意 |
| 管理成果 | 报告检查 | 报告上传、检查结果查看 |

### 咨询

咨询页不要只做聊天列表，它要承接三个上下文入口：

| 入口 | 触发位置 | AI 要带入的上下文 |
| --- | --- | --- |
| 方案解读 | 干预方案详情 | 当前方案、健康档案、近期指标 |
| 待办指导 | 待办详情 | 当前任务、计划时间、任务说明、关联指标 |
| 近况解读 | 近况分析详情 | 近期指标、记录、方案、待办完成情况 |

同时保留服务团队沟通：

| 页面 | 作用 |
| --- | --- |
| AI 健管师 | 通用问答 + 场景解读 |
| 服务团队沟通 | 找医生/健管师处理真实服务问题 |
| 咨询历史 | 回看 AI 或团队沟通记录 |

### 我的

我的页只处理身份、签约和设置，不承担核心健康管理动作。

| 页面 | 作用 |
| --- | --- |
| 我的签约 | 查看当前服务、历史服务、服务状态 |
| 签约详情 | 服务时间、团队、权益、状态 |
| 实名认证 | 影响档案、任务提醒、服务关联 |
| 设备管理 | 体脂秤等设备绑定和查看 |
| 消息授权 | 小程序订阅消息授权 |
| 账号设置 | 资料、退出等基础设置 |

## 4. 三条核心业务线

### A. 干预方案线

```text
首页方案摘要
→ 干预方案列表
→ 干预方案详情
→ AI 解读方案
→ 生成/查看相关待办
```

方案类型：

| 类型 | 是否首期重点 |
| --- | --- |
| 饮食方案 | 是 |
| 运动方案 | 是 |
| 监测方案 | 是 |
| 随访计划 | 是 |
| 用药指导 | 可后置 |
| 健康周报 | 可后置 |
| 阶段性报告 | 可后置 |

### B. 待办任务线

```text
首页今日待办
→ 待办详情
→ 完成任务 / 跳转记录
→ AI 指导怎么完成
→ 数据回流档案
```

待办状态：

```text
今日 / 未来 / 已完成 / 已过期 / 已取消
```

待办可关联：

```text
指标录入 / 饮食记录 / 运动记录 / 随访表单 / 报告上传 / 服务团队沟通
```

### C. 近况分析线

```text
首页近况分析
→ 近况分析详情
→ AI 解读近况
→ 推荐今日行动或方案重点
```

近况分析来源：

```text
健康档案
指标记录
饮食运动记录
随访记录
待办完成情况
生效中的干预方案
```

## 5. 页面优先级

### P0：先画、先定规则

| 页面 | 原因 |
| --- | --- |
| 首页 | 决定 C 端整体框架 |
| 档案首页 | 承接健康数据和方案 |
| 干预方案列表 | 方案展示的入口 |
| 干预方案详情 | 方案内容的核心承载 |
| 待办列表 | 执行体系入口 |
| 待办详情 | 执行动作核心页 |
| 指标总览 | 健康档案基础页 |
| 指标录入 | 数据回流基础动作 |

### P1：第二批细化

| 页面 | 原因 |
| --- | --- |
| 近况分析详情 | 首页分析的展开页 |
| AI 健管师 | 解读和指导能力入口 |
| 方案解读 | AI 与方案结合 |
| 待办指导 | AI 与执行结合 |
| 服务团队沟通 | 真人干预连接 |
| 饮食运动记录 | 减重/控糖场景重要 |
| 随访详情 | 管理端内容同步给患者 |

### P2：后续补齐

| 页面 | 原因 |
| --- | --- |
| 推荐内容列表/详情 | 低于方案和待办 |
| 用药/取药记录 | 可跟用药指导一起推进 |
| 报告单上传 | 依赖具体业务场景 |
| 服务团队主页 | 服务展示增强 |
| 设备管理 | 非所有客户必需 |
| 消息授权 | 配套能力 |

## 6. 当前结论

C 端页面结构先按这条主路径展开：

```text
首页看近况和今日行动
→ 进入方案或待办详情
→ 必要时问 AI 或服务团队
→ 完成任务并记录数据
→ 数据回到档案
→ 影响下一轮近况分析和待办
```

这比“功能菜单式页面结构”更符合慢管的产品核心。
