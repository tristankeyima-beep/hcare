# AIHcare C端整体体验重构需求

> 面向 UI/UX 设计师。  
> 目标不是重画旧页面，而是在理解现有能力和慢管业务闭环后，重新定义 C 端整体体验框架。

## 1. 定位

AIHcare C 端是一个由 **服务团队 + AI/科技能力** 共同支撑的慢病管理工具。

它不是资讯社区、营销页、商城，也不是单纯的健康档案查看器。它要帮助患者在长期管理周期里：

```text
看懂状态 → 理解计划 → 完成行动 → 记录数据 → 获得反馈 → 进入下一轮调整
```

患者打开小程序时，应能感知到四件事：

1. 有人在持续管理我。
2. 我知道今天该做什么。
3. 我的健康状态被理解和解释了。
4. 我处在一个长期健康计划中。

## 2. 核心业务模型

C 端体验按慢管 PDCA 闭环组织，而不是按后台功能列表组织。

```text
P 计划：服务团队 / 系统制定控制目标、监测计划、饮食方案、运动方案、随访计划等
D 执行：患者完成健康任务、指标记录、饮食运动记录、用药确认、报告上传等
C 检查：系统汇总档案、指标、任务、随访和方案执行情况，形成近况反馈
A 调整：服务团队和 AI/系统根据反馈调整方案、任务和下一步指导
```

对应到现有能力：

```text
健康档案 / 指标 / 饮食运动 / 随访 / 报告
→ 健康画像 / 近况分析 / 阶段反馈
→ 干预方案 / 控制目标 / 监测计划
→ 健康任务 / 今日行动 / 记录打卡
→ 数据回流
→ 服务团队 + AI 继续调整
```

设计重点：记录、任务、方案、咨询、状态反馈不是五个入口，而是同一个健康管理循环里的不同角色。

## 3. 当前能力边界

### 已有能力

这些能力已有业务基础，前端需要重新组织和承接：

| 能力 | 内容 |
| --- | --- |
| 健康档案 | 指标记录、指标趋势、饮食运动记录、随访记录、报告检查 |
| 干预方案 | 控制目标、饮食方案、运动方案、监测方案、随访计划、用药指导、健康周报 |
| 服务团队 | 医生/健管师、留言/咨询、签约服务 |
| 账户服务 | 实名认证、设备管理、消息授权、签约详情、报告上传 |

### 即将研发能力

这些能力马上进入开发，需要设计先行定义体验：

| 能力 | 内容 |
| --- | --- |
| 健康任务 | 首页任务卡片、任务列表、任务详情弹框、图片/二维码、未完成任务、完成动作 |
| AI 能力 | 基础 AI 对话、近况分析、方案解读、任务指导、AI 健管师 |

## 4. 关键产品判断

健康档案：不是资料库，而是数据底座。它支撑近况分析、方案调整、任务生成和服务团队判断。
干预方案：不是静态文档，而是阶段计划。饮食、运动、监测、随访、用药等方案需要被患者理解，并进一步拆成行动。
健康任务：不是普通待办列表，而是“计划到执行”的承接层。前台不一定叫“任务”，可以表达为“今日行动”“今日重点”“已为你整理好”。
AI 能力：不能变成孤立聊天壳。AI 的角色是整理、解释、指导和连接：整理档案和方案 → 解释为什么做 → 指导怎么做 → 连接服务团队
服务团队：是信任来源和责任主体。患者应感知到“AI/系统在整理，服务团队在跟进”，而不是只有机器在管理。

## 5. 设计开放边界

现有“首页 / 档案 / 咨询 / 我的”只作为能力参考，不要求机械沿用。设计师可以重新组织一级入口、页面分组和首页信息优先级。

但无论怎么重构，患者必须能清楚找到：

1. 当前状态。
2. 管理计划。
3. 今日行动。
4. 数据记录。
5. 服务/咨询。
6. 个人服务信息。

可以调整：

1. 一级导航结构。
2. 首页是否作为 AI 整理后的健康管理总览。
3. 方案、任务、档案、咨询之间的连接方式。
4. 信息前置、合并、下沉、重命名方式。
5. AI 与服务团队共同出现的方式。

不应偏离：

1. 工具属性优先。
2. 慢病管理闭环优先。
3. 服务团队 + AI/科技能力共同支撑。
4. 患者执行和数据回流是核心。
5. 不做内容社区化、营销化、活动化。
6. 不做后台功能菜单。

## 6. 设计命题

请重点回答：

1. C 端整体体验框架如何组织，才能让患者感知到自己处在长期健康管理计划中？
2. 首页如何表达当前阶段、团队关注点、今日行动和近况反馈？
3. 健康任务如何从首页进入列表和详情，并成为方案到执行的承接层？
4. AI 如何参与整理、解释和指导，同时不削弱服务团队的可信感？
5. 档案、方案、任务、咨询、近况反馈之间如何形成连续体验？
6. 患者如何知道“我今天做的记录和任务，会影响下一轮管理”？

## 7. 设计交付优先级

### 第一批：核心框架与主路径

第一批用于定 C 端整体体验框架，优先级最高。

必须包括：

1. 首页：重点体现健康任务和基础 AI 能力。
2. 首页待办任务卡片：让患者看到今日重点行动。
3. 待办任务列表：承接首页卡片，展示今日/近期任务。
4. 待办任务详情弹框：解释为什么做、怎么做、是否需要咨询。
5. 基础 AI 对话：围绕当前任务、当前页面和基础健康问题提供解释/求助入口。
6. 档案首页：体现各类数据看板，包括指标、饮食运动、人体成分、随访、报告等。
7. 我的页：承接签约服务、个人服务信息、设备、报告上传、账户设置等。

第一批要定清楚：

1. 患者进入 C 端后如何看到今日行动。
2. 任务如何从首页进入列表和详情。
3. AI 对话如何作为解释和求助入口出现。
4. 档案首页如何体现数据底座和健康看板。
5. 我的页如何承接个人服务信息，而不抢占健康管理主路径。

### 第二批：干预方案与 AI 解读

需要包括：

1. 各类干预方案在首页中的体现，例如阶段计划卡片、当前管理重点卡片、与今日行动相关的说明卡片。
2. 各类干预方案在 AI 对话中的解读，例如“帮我解读这个方案”“为什么适合我”“今天应该怎么执行”。
3. 各类干预方案详情页，包括控制目标、监测方案、饮食方案、运动方案、随访计划、用药指导、健康周报等。

第二批重点：把干预方案从静态查看，转成患者能理解、能被 AI 解释、能进一步拆成行动的阶段计划。

### 第三批：边缘页面与操作流程

需要包括：

1. 指标录入详情页。
2. 随访记录页。
3. 报告上传、历史记录等辅助页面。
4. 智能设备连接流程。
5. 其他记录、设置、空状态、异常状态页面。

第三批重点：补齐一致性和可用性，不反向影响第一批框架。

## 9. 视觉与文案方向

视觉关键词：

```text
可信医疗 / 温和陪伴 / 清晰行动 / 智能整理 / 工具化
```

光效与动效方向：

1. 需要适度体现光效和动效，强化“AI 正在整理、分析、生成建议”的产品感知。
2. 光效用于服务信息层级和状态反馈，例如今日重点、AI 分析中、任务完成、数据回流、服务团队跟进。
3. 动效应轻量、克制、可落地，重点用于页面转场、卡片展开、任务完成、AI 回复生成、数据更新等关键节点。
4. 医疗健康场景要保持可信和稳定，动效不能干扰阅读、操作和老年用户理解。

文案方向：

1. 多用“已为你整理好”“今日重点”“建议先关注”“服务团队会继续跟进”。
2. 少用“异常”“严重”“必须”“逾期”“漏做”等压迫性表达。
3. 对患者说人话，少暴露系统内部机制。
4. AI 和服务团队自然融合，不让患者理解复杂分流逻辑。

## 10. 不希望出现的方向

1. 只是给旧页面换皮。
2. 首页仍然是功能宫格或入口集合。
3. 做成资讯流、社区或营销活动页。
4. AI 只是一个孤立聊天入口。
5. 服务团队被弱化成普通客服。
6. 档案只是冷冰冰的数据仓库。
7. 医疗术语过多，患者看不懂。
8. 过度强调风险、异常、惩罚，制造焦虑。
9. 光效和动效只做装饰，影响信息理解和操作效率。
