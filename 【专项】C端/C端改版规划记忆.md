# C端改版规划记忆

> 本文档记录 C 端小程序改版过程中的核心产品判断。后续首页、档案、待办、AI 健管师、内容推荐、管理端联动等设计，都应以此为基础。

## 慢管产品核心

慢管的产品核心不是单纯展示功能，而是建立 AI 共管闭环：

```text
健康档案/随访/指标/饮食运动记录
→ AI 生成成果物
→ AI 生成 TodoList
→ 患者执行
→ 新数据回流
```

这个闭环要求 C 端不只是“看信息”的入口，而是患者执行健康管理动作、理解健康管理内容、持续产生数据回流的终端。

## C端整体设计的两条线

### 第一条线：C端要有自己的产品框架

无论管理端能力多完善，AI 能帮健管师生成多少交付物，交付物形式多丰富，C 端都不能只是管理端能力的被动承接页。C 端需要有自己的稳定框架，用患者能理解和能执行的方式组织信息。

当前确定的 C 端框架主要包括：

1. 待办
2. 近况分析
3. 指标记录和查看，即健康档案
4. 推荐，包括内容推荐、图文、视频

这个框架的设计重点是：患者打开小程序后，应先知道“我现在怎么样、今天该做什么、为什么要做、做完后有什么反馈”，而不是面对一组后台功能入口。

### 第二条线：C端要和管理端的健管师建立连接

C 端框架中的每个组件，都要考虑如何帮助管理端的健管师更好地干预患者。C 端不是孤立患者端，而是管理端服务能力触达患者的表达层。

因此，C 端组件需要沿两个方向分化：

1. 根据管理端配置进行规范化展示
2. 通过 AI 生成更贴合患者实际情况的展示内容

前者是固定配置，依赖管理端人工配置、规则配置和结构化交付；后者是智能化内容，能更贴合患者当前状态，但需要额外交付成本。

## 配置化与AI生成的产品分层

### 配置化展示

配置化展示是基础能力，适用于客户只购买基础慢管系统或不启用 AI 模块的情况。

特点：

- 内容来自管理端人工配置、模板配置、规则配置或健管师手动创建。
- 展示结构稳定，便于交付、验收和规模化复制。
- 人工工作量较高，个性化有限。
- 适合作为基础版 C 端能力。

典型内容：

- 管理端配置的待办任务
- 健管师制定的监测计划、随访计划、饮食运动方案
- 固定健康资讯、图文、视频
- 结构化指标目标、提醒规则、签约服务信息

### AI生成展示

AI 生成展示是增值能力，适用于客户购买 AI 模块并承担 token 成本的情况。

特点：

- 内容基于患者真实健康档案、随访、指标、饮食运动记录、历史执行情况生成。
- 更贴合患者当前状态，能解释原因、给出下一步动作。
- 能减少健管师重复配置和解释成本。
- 需要明确作为 AI 模块能力收费，并计算 token 成本。

典型内容：

- AI 生成或重排 TodoList
- AI 生成近况分析
- AI 解读饮食方案、运动方案、用药指导、健康周报
- AI 根据患者状态生成个性化内容推荐
- AI 辅助把管理端交付物转成患者能执行的今日行动

## 对后续设计的约束

1. C 端首页优先服务“今日状态”和“今日行动”，不能退化成服务入口堆叠。
2. 待办不是普通任务列表，而是管理方案落地到患者执行的核心承接层。
3. 近况分析要连接健康档案和待办，解释“为什么今天要做这件事”。
4. 健康档案不仅给患者查看，也要为 AI 生成成果物和健管师干预提供数据底座。
5. 推荐内容不应只是运营资讯，应逐步支持根据患者状态和管理目标进行个性化推荐。
6. 每个 C 端组件都要同时考虑基础配置版和 AI 增强版，方便形成产品套餐和商业化边界。
7. AI 能力要明确体现价值：更个性化、更少人工、更强执行转化，而不是只增加一个聊天入口。
