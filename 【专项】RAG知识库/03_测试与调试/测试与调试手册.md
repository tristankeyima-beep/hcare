# Dify 知识库测试与调试手册

## 1. 安全约定

本目录不保存 API Key、知识库 ID 或任何可直接访问线上系统的凭据。运行命令前在终端临时设置：

```bash
export DIFY_BASE='https://<your-dify-host>/v1'
export DIFY_DATASET_ID='<dataset-id>'
export DIFY_DATASET_TOKEN='<dataset-api-key>'
```

不要把以上环境变量写入 Markdown、脚本、Git 或客户端代码。

## 2. 先检查“已保存”的线上配置

界面上的单选状态不等于线上已经生效；修改检索配置后必须点击保存，并用 API 回读确认。

```bash
curl -sS "$DIFY_BASE/datasets/$DIFY_DATASET_ID" \
  -H "Authorization: Bearer $DIFY_DATASET_TOKEN"
```

重点检查：

- `search_method` 应为 `hybrid_search`；
- 权重模式的 `reranking_mode` 应为 `weighted_score`；
- 权重为语义 0.7、关键词 0.3；
- `top_k` 为 4，且未启用分数阈值。

注意：某些 Dify 版本会保留 `reranking_enable: true`，但只要 `reranking_mode` 为 `weighted_score`，最终使用的是权重融合，不是模型 Rerank。

## 3. 命中测试（以线上已保存配置为准）

不要在请求中传 `retrieval_model` 覆盖配置，才能验证用户界面实际保存的设置。

```bash
curl -sS -X POST "$DIFY_BASE/datasets/$DIFY_DATASET_ID/retrieve" \
  -H "Authorization: Bearer $DIFY_DATASET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"query":"BMI 24.0–27.9 的超重人群如何安排运动？"}'
```

记录每条结果的：问题、命中分段标题/内容前 200 字、分数、Top 1 是否直接回答问题、Top 4 是否包含正确依据。评估时不要只看“能否搜到”，还要看是否把正确证据排在前面。

## 4. 诊断顺序

1. **文档状态**：查询文档状态是否为 `completed`，确认不是仍在索引。
2. **分段存在性**：用分段列表接口按“表 4”“司美格鲁肽”等关键词定位父分段。
3. **父子关系**：对子分段列表接口检查子块。父块是上下文，子块才是检索对象。
4. **固定问题集复测**：改一个因素，只复测同一组问题，避免凭单题感受下结论。
5. **再做配置 A/B**：比较权重融合与 Rerank，而不是只换模型名。

## 5. 常用接口

```bash
# 文档列表
curl -sS "$DIFY_BASE/datasets/$DIFY_DATASET_ID/documents?page=1&limit=20" \
  -H "Authorization: Bearer $DIFY_DATASET_TOKEN"

# 父分段列表：keyword 可替换为“表 4”
curl -sS "$DIFY_BASE/datasets/$DIFY_DATASET_ID/documents/$DIFY_DOC_ID/segments?page=1&limit=100&keyword=%E8%A1%A8%204" \
  -H "Authorization: Bearer $DIFY_DATASET_TOKEN"

# 子分段列表
curl -sS "$DIFY_BASE/datasets/$DIFY_DATASET_ID/documents/$DIFY_DOC_ID/segments/$DIFY_PARENT_ID/child_chunks?page=1&limit=20" \
  -H "Authorization: Bearer $DIFY_DATASET_TOKEN"
```

## 7. 关键限制与后续原则

- Dify 的**父分段**更新接口支持 `keywords`；**子分段**更新接口只支持 `content`，没有独立关键词字段。
- 更新子分段后，应同步更新清洗源 Markdown；否则下次整文重新上传会覆盖人工修改。
- 表格是高风险检索对象。若它承担慢病管理系统中的关键决策，建议在清洗 Markdown 中另建短小、可独立回答的问答块，而不是只依赖大表格。
- 不要以一次命中或一次不命中判断检索策略；至少用 `检索测试集.md` 的问题集做 Top 1 / Top 4 对照。
