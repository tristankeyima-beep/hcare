# AI 工作流编排概要

本文档概要说明 AI 生成健康管理计划时，围绕待办任务进行调整的工作流编排逻辑。

## 一、总体思路

工作流采用“代码处理事实、LLM 进行判断、代码执行解析与校验”的方式。

LLM 不直接生成完整任务，也不直接落库。LLM 只负责生成任务调整指令；后续由代码节点根据指令、原始任务和默认动作集生成正式的新增、编辑、删除结果。

## 二、工作流主线

```text
1. 数据处理代码节点
   ↓
2A. 待办任务摘要生成代码节点
2B. 管理画像生成 LLM 节点
   ↓
3. 任务调整指令 LLM 节点
   ↓
4. 指令解析代码节点
   ↓
5. 规则校验代码节点
   ↓
6. 输出最终任务调整方案
```

## 三、节点说明

### 1. 数据处理代码节点

负责处理原始入参，统一字段格式和枚举值，计算逾期、剩余有效天数等事实字段，并补齐任务与签约产品、服务团队之间的关联。

该节点不做任务调整判断，只负责把数据整理成稳定、可计算的结构。

### 2A. 待办任务摘要生成代码节点

负责把完整待办任务压缩成给 LLM 阅读的待办任务摘要。

待办任务摘要包含任务 ID、简短描述和中文业务标签。业务标签用于帮助 LLM 快速理解任务状态，例如已逾期、任务目的模糊、服务团队执行、分层管理来源、不建议删除等。

该节点的目标是减少 LLM 阅读完整任务数据的负担。

### 2B. 管理画像生成 LLM 节点

负责生成精简管理画像。

管理画像只需要说明患者本期重点需要干预、介入和提醒自我管理的内容，不需要复杂层级结构。
如果包含服务包信息，还要说明服务内容。
该节点输出会作为任务调整指令的判断依据，因此内容要简洁但准确。

### 3. 任务调整指令 LLM 节点

负责基于管理画像和待办任务摘要，生成新增、编辑、删除三类任务调整指令。

该节点不输出完整任务对象，只输出精简指令：

- 新增：说明新增哪类任务、计划完成时间、本次任务说明重点和新增原因。
- 编辑：说明编辑哪条原任务、需要修改哪些字段和编辑原因。
- 删除：说明删除哪条原任务和删除原因。

编辑指令中的 `patch` 只允许包含 4 类字段：

```text
planned_time
valid_days
task_name
description
```

原因使用面向管理者展示的自然语言说明。若后续需要统计或质检分类，可再增加原因编号。

任务调整指令示例：

```json
{
  "task_change_instructions": {
    "create": [
      {
        "template_code": "3",
        "reference_task_id": "TASK-001",
        "planned_time": "2026-06-16 08:00:00",
        "instruction_note": "提醒患者在早餐前完成空腹血糖测量并上传记录。",
        "reason_text": "患者本期需要关注血糖控制，但当前待办任务中缺少可承接空腹血糖监测的有效任务。"
      }
    ],
    "edit": [
      {
        "task_id": "TASK-001",
        "patch": {
          "planned_time": "2026-06-15 10:00:00",
          "description": "提醒患者按计划完成本周GLP-1注射，并确认是否出现不适。"
        },
        "reason_text": "原任务已逾期且说明较简单，建议调整履约时间并补充注射执行确认内容。"
      }
    ],
    "delete": [
      {
        "task_id": "TASK-004",
        "reason_text": "该任务已逾期28天且内容较泛，继续保留会干扰本期更具体的管理任务安排。"
      }
    ]
  }
}
```

一句话总结：新增是选模板、定时间、写本次说明并给出原因；编辑是选原任务、给出修改字段并说明原因；删除是选原任务并说明原因。

### 4. 指令解析代码节点

负责把 LLM 输出的调整指令转成正式任务调整方案。

新增任务时，代码节点根据任务类型编号读取默认动作集，并结合参考任务、签约服务和 LLM 给出的计划时间、任务说明补齐字段。

编辑任务时，代码节点根据原任务 ID 找到原任务，只应用 LLM 指令中给出的修改字段。

删除任务时，代码节点根据原任务 ID 生成删除候选。

### 5. 规则校验代码节点

负责对正式任务调整方案进行落地前校验。

重点校验内容包括：任务 ID 是否存在、同一任务是否被重复操作、新增模板编号是否存在、计划时间是否超过签约有效期、编辑 `patch` 是否只包含允许字段、分层管理和分标管理来源任务是否满足保留要求等。

校验不通过时，不直接落库，应返回修正或进入人工确认。

### 6. 输出最终任务调整方案

校验通过后，输出最终任务调整方案。

最终结果按新增、编辑、删除分组，供业务系统执行或供管理者确认。

## 四、关键边界

- 给 LLM 看的内容使用中文短语，便于理解。
- 给代码节点执行的指令使用短码，便于解析。
- LLM 负责判断，不负责补齐完整任务字段。
- 代码节点负责解析、补字段和规则兜底。
- 管理画像是任务调整的依据，不能和任务调整结果混在一起。
- 新增任务优先通过默认动作集生成，避免 LLM 自由生成完整任务。
