# AI 健管师 Agent Harness 设计

日期：2026-08-04

## 1. 目标

AI 健管师面向健管师提供三类连续能力：

1. 查询患者健康档案和相关健康上下文；
2. 从单个患者或责任人群中发现需要管理的患者问题，说明问题及证据，并提出管理建议；
3. 在健管师选择建议后，生成一个或多个患者专属交付物草稿。

首期的产品闭环是：

```text
找到该管的人
→ 说明患者有什么问题及证据
→ 提出管理建议
→ 健管师选择
→ 生成可审阅的干预方案或创作型作品草稿
```

AgentScope 提供 Agent、工具、记忆、运行轨迹等通用能力。本设计定义与慢管业务相关的 Harness，包括扫描入口、权限、上下文装配、问题合并、证据引用、人工控制、安全边界和评测。

## 2. 首期范围

### 2.1 包含

- 单患者手动扫描；
- 按条件选择人群后手动扫描；
- 按健管师责任范围进行定时人群扫描；
- 读取慢管系统患者基础档案、专病档案、近期指标、用药、饮食、运动和指标上传记录；
- 使用固定规则与 Agent 综合分析发现患者问题；
- 持久化患者问题，合并重复扫描产生的相同问题；
- 展示患者问题、证据、重要程度及管理建议；
- 健管师选择一个或多个管理建议后生成交付物；
- 生成干预方案草稿或创作型作品草稿；
- 所有交付物绑定具体患者和患者问题；
- 记录来源引用、模型版本、规则版本和运行轨迹；
- 评测运行可靠性、问题可信度、证据可靠性和产出可用性。

### 2.2 不包含

- 患者待办、任务提醒和任务完成状态；
- 向慢管系统写入干预方案或其他业务数据；
- 自动触达患者；
- 自动执行管理动作；
- 基于患者数据变更事件的实时扫描；
- 通用作品素材库或跨患者作品复用；
- 将所有来源预处理成统一的医学原子事实库或知识图谱。

未来取得慢管系统写接口后，在现有流程末端增加人工确认、执行适配器、结果验证和审计，不改造前面的扫描、判断和生成主链。

## 3. 产品核心模型

产品只向健管师呈现三个核心概念：

```text
患者问题 → 管理建议 → 交付物
```

### 3.1 患者问题

患者问题回答：

- 哪个患者存在什么问题；
- 判断证据是什么；
- 问题是否重要或紧急；
- 哪些内容是客观数据，哪些是规则判断或 Agent 推断；
- 问题首次和最近一次被发现的时间。

相同患者的相同问题在后续扫描中更新证据和趋势，不重复创建。问题明显恶化或出现关键新证据时，重新进入待查看状态。

最小状态为：

```text
待查看 → 已忽略
      → 已采纳 → 已生成交付物
```

状态用于管理扫描结果，不代表患者待办。

### 3.2 管理建议

管理建议回答：

- 针对当前患者问题建议做什么；
- 为什么建议这样做；
- 建议生成哪类交付物。

一个患者问题可以有多个管理建议。Agent 可以主动提出建议，但健管师选择后才生成完整交付物。

### 3.3 交付物

首期交付物分为：

- 结构化干预方案草稿；
- 创作型作品草稿，例如患者宣教材料、沟通内容和阶段总结。

一次选择可以生成多个交付物。每个交付物必须绑定患者、患者问题和被选择的管理建议，并保留内容版本、编辑记录和审核状态。

## 4. 总体架构

采用分阶段混合型 Harness：

```text
扫描触发
→ 权限及范围校验
→ 候选患者筛选
→ 患者健康上下文装配
→ 固定规则判断 + Agent 综合分析
→ 患者问题归并和保存
→ Agent 提出管理建议
→ 健管师选择
→ Agent 生成交付物草稿
→ 草稿箱编辑与审核
```

确定性程序负责：

- 租户、机构、健管师和患者数据权限；
- 扫描触发方式、范围、分页和批次；
- 慢管 API 调用、超时和失败隔离；
- 固定规则和高风险兜底；
- 原始来源登记及引用校验；
- 相同患者问题归并；
- 患者问题与交付物状态；
- 人工选择控制点；
- 日志、追踪、成本和评测记录。

AgentScope Agent 负责：

- 基于多类健康材料发现规则以外的复杂患者问题；
- 判断是否需要继续调用只读工具补查数据；
- 综合材料解释患者为什么需要管理；
- 输出患者问题、判断说明和来源引用位置；
- 提出管理建议；
- 根据健管师选择生成交付物内容。

首期不采用多个业务 Agent 自由讨论的组织型架构。分析和生成可以使用不同的 Agent 配置，但都运行在确定性的阶段控制中。

## 5. 扫描入口和执行流程

### 5.1 单患者手动扫描

健管师在患者场景中触发。Harness 校验患者属于当前可访问范围，加载标准健康摘要，再由规则和 Agent 分析。

### 5.2 人群手动扫描

健管师选择患者筛选条件后触发。Harness 使用慢管患者列表及指标上传记录接口筛选候选患者，分页处理并逐个分析。

### 5.3 定时人群扫描

系统按配置周期扫描健管师责任人群。每个健管师、机构和租户的扫描范围隔离。一个患者失败不影响其他患者或整个批次完成。

### 5.4 后续事件触发

未来慢管系统提供稳定的数据事件或消息机制后，可将患者指标更新等事件转换为新的扫描入口。事件触发仍复用同一条分析链路。

## 6. 患者健康上下文

采用混合装配方式：

1. Harness 默认准备标准患者健康摘要；
2. Agent 判断信息不足时，可以调用经过授权的只读工具查询明细；
3. 只查询当前任务所需的最小数据，不默认加载全部历史；
4. 每次补充查询都重新校验租户、机构、健管师和患者范围。

标准摘要可包含基础档案、专病档案、近期健康指标和数据新鲜度。药品明细、指定时间段饮食运动、历史指标上传记录等作为按需查询工具。

AgentScope Memory 不替代业务患者档案。患者事实以慢管系统和当次登记的来源材料为准；Memory 只保存本次 Agent 工作所需的对话与运行状态。

## 7. 规则与 Agent 混合判断

固定风险和明确阈值由规则稳定召回；复杂趋势、跨材料关系和管理机会由 Agent 补充发现。

每个患者问题记录发现来源：

- 规则发现；
- Agent 发现；
- 规则与 Agent 共同支持。

固定高风险规则优先。Agent 可以补充解释和建议，但不得删除、覆盖或降低固定规则给出的风险等级。

## 8. 来源、证据引用和关联推理

### 8.1 原始来源登记

任何供 Agent 使用的材料先登记为不可修改的来源。来源包括：

- 慢管 API 响应；
- Chatbox 消息或人工粘贴文本；
- 上传文件及其可检索文本；
- 图片及 OCR 结果。

来源至少记录：

- `source_id`；
- 来源类型；
- 患者、租户和机构；
- 来源系统记录 ID、消息 ID 或文件 ID；
- 数据发生时间和读取时间；
- 原始内容受控快照或可回查定位；
- 内容哈希；
- 当前访问权限。

不得把所有来源预先转换为高度结构化的原子事实。结构化慢管数据和非结构化文本都直接作为大模型可理解的上下文材料。

### 8.2 模型输出引用位置

Agent 输出患者问题时，同时输出每项判断使用的来源和定位信息：

- API 数据：来源 ID、业务记录 ID、JSONPath 或字段路径；
- Chatbox：消息 ID、字符起止位置或完整消息引用；
- 文件：文件 ID、页码、段落或字符位置；
- 图片：图片 ID、OCR 文本位置或区域坐标。

### 8.3 Harness 引用校验

Harness 在保存患者问题前校验：

- 来源属于当前患者及权限范围；
- 定位信息真实存在；
- 引用的数字、单位、时间和限定词没有被模型篡改；
- 判断说明没有把推断伪装成原始事实。

校验成功后，为实际使用的引用生成内部 `evidence_id`。未被使用的原始材料不需要提前生成证据记录。

### 8.4 关联推理

患者问题保存简化的推理链：

```text
来源引用 → 中间判断 → 患者问题 → 管理建议
```

中间判断可以同时引用多个来源，并标记证据的作用是支持、补充或冲突。推断必须与原始来源引用分开保存；推断不能在后续运行中被当作新的客观事实。

不要求使用图数据库。普通关系表或 JSON 结构能够保存结论与引用关系即可。

## 9. 重复问题归并

定时扫描不能反复生成相同提醒。Harness 根据患者、问题类型及有效时间范围识别是否为同一问题：

- 首次发现时创建患者问题；
- 后续扫描更新证据、最近发现时间、趋势和重要程度；
- 变化不大时不重复提醒；
- 明显恶化或出现关键新证据时重新进入待查看；
- 已忽略的问题也可以因显著变化重新出现。

问题归并属于内部机制，不作为新的产品概念展示给健管师。

## 10. 人工控制

首期采用草拟型自治：

- Agent 可以自动扫描、发现患者问题和提出管理建议；
- Agent 不自动生成所有完整交付物；
- 健管师先查看患者问题和证据，再选择一个或多个建议；
- 只有被选择的建议才触发交付物生成；
- 交付物保存在患者作品草稿箱，可编辑和审核；
- 首期不自动写回慢管系统，也不触达患者。

未来可按动作风险逐步增加自动执行能力，但执行权限不由 Agent 自行决定。

## 11. 异常处理

### 11.1 数据不完整

系统明确记录缺少的材料。Agent 只能基于已取得的数据判断。关键资料缺失时不生成患者问题，返回本次无法完成分析及缺失原因。

### 11.2 引用校验失败

患者问题不得入库。可以把校验错误反馈给 Agent 修正一次；再次失败则放弃该候选问题，并记录脱敏运行错误。

### 11.3 单患者失败

人群扫描中只失败当前患者，不中断整个批次。批次结束后记录成功、跳过和失败数量。

### 11.4 模型超时或输出不合规

执行有限次数重试。仍失败时保留运行结果和错误分类，但不生成空白、无引用或猜测性患者问题。

### 11.5 慢管接口鉴权失败

按现有对接约定仅执行一次重新鉴权及原请求重试，禁止无限重试。生产环境使用机器账号的最小必要权限，不长期依赖健管师用户会话凭证。

## 12. 安全与隐私

- 所有慢管 API 只能由 Agent 后端调用；
- 每次读取都校验租户、机构、健管师和患者数据范围；
- 患者健康信息按最小范围查询并最短时间缓存；
- 权限变化后不得继续展示已无权访问的来源原文；
- 日志只记录链路 ID、来源 ID、HTTP 状态、业务码和脱敏错误；
- 不记录账号密码、Token、患者完整档案或完整作品内容；
- Chatbox 人工材料记录提供者及时间，明确其为人工提供或患者自述，不能冒充客观设备事实；
- 所有患者问题和交付物记录使用的模型、Prompt、规则和工具版本。

## 13. AgentScope 能力映射

| Harness 需求 | AgentScope 用法 |
| --- | --- |
| 分析和内容生成 | 使用受阶段控制的 ReAct Agent 或等价 Agent |
| 慢管查询 | 注册为只读 Tool；工具内部执行权限和患者范围校验 |
| 标准上下文与按需补查 | Formatter、Memory 与只读 Toolkit 配合 |
| 人工选择后生成 | 业务工作流控制 Agent 调用，不由 Agent 自行绕过 |
| 状态恢复 | 保存 Agent 运行状态和业务运行 ID |
| 运行追踪 | Tracing 记录模型、工具、引用、耗时和用量 |
| 结构化输出 | 约束患者问题、管理建议、引用位置和交付物元数据的输出结构 |
| 未来执行扩展 | 增加独立写工具及审批中间件，不向分析 Agent 直接开放写权限 |

患者问题、交付物、来源登记和权限属于业务数据，应保存在业务持久层，不依赖 AgentScope 会话 Memory 作为唯一存储。

## 14. 评测与验收

### 14.1 运行可靠性

- 慢管接口查询成功率；
- 单患者和人群扫描完成率；
- 单患者失败隔离正确性；
- 扫描耗时、模型调用次数和成本；
- 定时扫描重复执行的幂等性。

### 14.2 患者问题可信度

- 问题识别准确性；
- 重要问题和固定高风险问题召回；
- 无依据问题比例；
- 相同问题正确合并率；
- 数据不足时正确停止判断的比例。

### 14.3 证据可靠性

- 引用可定位率；
- 数字、单位、时间和限定词保真率；
- 客观事实与 Agent 推断区分正确率；
- 跨患者、跨机构引用错误数；
- 人工材料来源类型标记正确率。

### 14.4 产品可用性

- 健管师查看和采纳管理建议的比例；
- 被采纳建议生成交付物的比例；
- 健管师对交付物的修改幅度；
- 健管师有用性评分；
- 被忽略问题的抽样合理性。

### 14.5 评测方法

上线前建立脱敏真实病例评测集，覆盖常见问题、无问题、关键数据缺失、高风险、来源冲突和人工文本材料。由健管专家标注合理患者问题、关键证据、可接受建议和不可接受结论。

引用定位、数字保真和输出结构使用自动评测；医学合理性、管理价值和交付物可用性由健管专家复核。上线后持续记录查看、忽略、采纳、生成和修改行为，并对被采纳与被忽略结果同时抽样复核。

跨患者或跨机构数据泄露、伪造引用、固定高风险规则被 Agent 覆盖属于阻断性问题，不能由平均得分抵消。

## 15. 已确认的设计决策

- 首期采用草拟型，未来预留分级自治；
- 单患者、人群和定时扫描使用一套统一 Harness；
- 首期做到查询、扫描、分析、建议和交付物生成；
- 待办不进入首期范围；
- 一个患者问题可以产生多个管理建议和多个交付物；
- 采用规则与 Agent 混合判断；
- 先展示患者问题和建议，健管师选择后才生成完整交付物；
- 患者上下文采用标准摘要加 Agent 按需只读查询；
- 所有交付物绑定具体患者和患者问题；
- 患者问题持久化并合并重复扫描结果；
- 产品核心概念只保留患者问题、管理建议和交付物；
- 来源材料统一登记，但不预建高度结构化的原子事实库；
- Agent 输出来源定位，Harness 校验后保存实际使用的证据引用；
- 采用分阶段混合型架构，不使用首期多 Agent 自由组织架构。
