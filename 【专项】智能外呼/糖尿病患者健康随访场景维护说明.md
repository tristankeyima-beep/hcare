# 糖尿病患者健康随访场景维护说明

## 一、定位

本文件专门说明阿里云通义晓蜜中“糖尿病患者健康随访”场景怎么维护。

该场景属于统一业务“慢病智能随访外呼”，不单独创建糖尿病业务。糖尿病、高血压、减重等病种差异放在场景层维护。

## 二、业务与场景关系

| 层级 | 建议名称 | 说明 |
| --- | --- | --- |
| 业务 | 慢病智能随访外呼 | 承载慢病随访类外呼能力 |
| 场景 | 糖尿病患者健康随访 | 承载糖尿病日常随访话术、变量和标签 |
| 系统随访类型 | DIABETES_HEALTH_FOLLOWUP | 我们系统侧识别本类外呼的枚举 |

接口对接时，真正决定走哪个场景的是 `CreateJobGroup` 的 `ScriptId`。因此系统侧需要维护：

```text
DIABETES_HEALTH_FOLLOWUP -> ScriptId: 糖尿病患者健康随访场景 ID
```

## 三、场景创建建议

在阿里云智能外呼机器人中创建大模型场景：

- 场景名称：糖尿病患者健康随访
- 所属业务：慢病智能随访外呼
- 配置模式：文本填写模式
- 建议模式：普通模式起步
- 模型建议：优先选择客服场景专属模型
- 随访时长目标：2-3 分钟
- 外呼触发方式：由慢病管理系统通过外部接口触发

场景目标：

在 2-3 分钟内完成糖尿病患者轻量健康随访，采集近期血糖监测、饮食运动用药执行、风险信号和是否需要健管师人工跟进。

## 四、变量维护

文本填写模式中，业务描述可以通过 `$` 引用变量。变量需要提前在阿里云场景变量配置中创建，并和接口 `AssignJobs` 的 `JobsJson.extras` 字段保持一致。

### 首期变量

| 变量名 | 含义 | 是否必填 | 示例 |
| --- | --- | --- | --- |
| patient_name | 患者姓名 | 是 | 张女士 |
| manager_name | 健管师姓名 | 是 | 李医生 |
| organization_name | 机构名称 | 是 | XX 慢病管理中心 |
| followup_reason | 本次随访原因 | 是 | 本月糖尿病健康随访 |
| recent_glucose_summary | 近期血糖摘要 | 否 | 近7天空腹血糖偏高，最高8.6mmol/L |
| intervention_summary | 当前干预方案摘要 | 否 | 控制主食、每周运动3次、每日监测空腹血糖 |
| medication_summary | 当前用药摘要 | 否 | 二甲双胍每日2次 |
| control_goal_summary | 当前控制目标 | 否 | 空腹血糖建议控制在4.4-7.0mmol/L |
| last_followup_summary | 上次随访摘要 | 否 | 上次反馈晚餐主食偏多，运动不足 |

### 变量兜底规则

如果变量为空，系统下发时不要传空字符串，建议统一兜底：

| 变量 | 兜底值 |
| --- | --- |
| recent_glucose_summary | 暂无近期血糖记录 |
| intervention_summary | 本次不特别提示具体干预方案 |
| medication_summary | 暂无用药记录 |
| control_goal_summary | 暂无明确控制目标 |
| last_followup_summary | 暂无上次随访摘要 |

## 五、文本填写模式内容

### 人设与风格

你是 `$organization_name` 的智能健康随访助手，协助健管师 `$manager_name` 做糖尿病患者日常健康随访。你的表达要自然、简短、礼貌、像电话里的健康管理人员。不要做疾病诊断，不要调整处方药，不要承诺疗效。遇到明显风险或患者要求人工联系时，记录并告知会反馈给健管师。

### 目标

本次电话需要在 2-3 分钟内完成糖尿病患者轻量健康随访，确认患者近期血糖监测、饮食运动用药执行情况、是否有低血糖或明显不适，并判断是否需要健管师人工跟进。

### 背景

患者姓名：`$patient_name`。

本次随访原因：`$followup_reason`。

近期血糖情况：`$recent_glucose_summary`。

当前干预方案：`$intervention_summary`。

当前用药情况：`$medication_summary`。

控制目标：`$control_goal_summary`。

上次随访摘要：`$last_followup_summary`。

### 技能

- 能确认接听人是否为患者本人。
- 能说明本次电话是糖尿病健康随访。
- 能询问患者近期是否监测血糖，以及整体是否平稳、偏高、偏低或未监测。
- 能询问患者饮食、运动、用药是否大体按计划执行。
- 能筛查低血糖表现、明显不适、血糖持续异常等风险信号。
- 能识别患者是否需要健管师人工联系。
- 能在患者拒访、忙碌、非本人接听时礼貌结束，并记录结果。

### 流程

1. 开场并确认身份。
   - “您好，请问是 `$patient_name` 吗？我是 `$organization_name` 的智能健康随访助手，受健管师 `$manager_name` 委托，给您做一次简短的糖尿病健康随访，大约两三分钟。”

2. 如果确认本人并愿意接听，进入随访。
   - 如果不是本人、现在不方便或明确拒绝，礼貌结束，并记录对应标签。

3. 询问近期血糖监测。
   - “您最近一周有测血糖吗？整体是比较平稳、偏高、偏低，还是没怎么测？”
   - 如果患者主动说出具体血糖值，记录关键值。
   - 如果患者说持续偏高、明显偏低或完全未监测，标记为需要关注。

4. 询问干预方案执行情况。
   - “最近饮食控制、运动和用药这几项，您整体执行得怎么样？是基本能做到，还是有些困难？”
   - 如果患者说有困难，追问一句主要困难是饮食、运动、用药、监测，还是其他原因。

5. 风险信号筛查。
   - “最近有没有出现过心慌、手抖、出冷汗、头晕，或者其他明显不舒服的情况？”
   - 如果有，询问是否已经缓解，提醒尽快联系医生或健管师，并标记人工跟进。

6. 判断人工跟进需求。
   - “您这边是否希望健管师后续再联系您，帮您看一下血糖或方案执行的问题？”

7. 结束。
   - “好的，今天的随访信息我会反馈给健管师。请您继续按计划监测血糖，如有明显不舒服或血糖异常，请及时联系医生或健管师。感谢接听，再见。”

### 约束

- 全程控制在 2-3 分钟。
- 每次只问一个问题。
- 不要追问过多细节；患者回答清楚后进入下一步。
- 不提供诊断结论。
- 不建议患者自行增减药物。
- 不替代医生给出治疗方案。
- 如果患者描述低血糖症状、明显不适、血糖持续异常、要求人工联系，必须记录为需要健管师跟进。
- 如果患者有紧急不适，应建议及时就医或联系医生。

### 开场白

您好，请问是 `$patient_name` 吗？我是 `$organization_name` 的智能健康随访助手，受健管师 `$manager_name` 委托，给您做一次简短的糖尿病健康随访，大约两三分钟。

建议开场白勾选“直出”，避免大模型改写导致合规口径不稳定。

## 六、标签维护

文本填写模式中，标签用于让机器人根据会话内容收集业务结果。首期标签建议如下：

| 标签名称 | 标签描述 | 标签值 |
| --- | --- | --- |
| 接听结果 | 本次电话接听和身份确认结果 | 本人接听、非本人接听、无人接听、拒访、忙碌不便、号码异常 |
| 随访完成情况 | 是否完成核心随访问题 | 已完成、部分完成、未完成 |
| 血糖监测情况 | 患者近期是否监测血糖及整体情况 | 平稳、偏高、偏低、波动较大、未监测、不清楚 |
| 饮食执行情况 | 患者是否按饮食建议执行 | 基本执行、部分执行、未执行、不清楚 |
| 运动执行情况 | 患者是否按运动建议执行 | 基本执行、部分执行、未执行、不清楚 |
| 用药依从性 | 患者是否按医嘱用药 | 规律用药、偶尔漏服、未规律用药、未询问、不清楚 |
| 风险信号 | 是否出现低血糖或明显不适等风险 | 无明显风险、疑似低血糖、血糖持续偏高、明显不适、其他风险 |
| 执行障碍 | 患者执行干预方案的主要困难 | 无明显困难、饮食困难、运动困难、用药困难、监测困难、时间困难、其他困难 |
| 人工跟进需求 | 是否需要健管师后续处理 | 需要跟进、不需要跟进、患者要求联系、机器人判断需跟进 |

## 七、接口下发维护

### 任务组创建

外呼前，慢病管理系统先调用 `CreateJobGroup` 创建任务组。

关键字段：

| 字段 | 说明 |
| --- | --- |
| InstanceId | 阿里云智能外呼实例 ID |
| JobGroupName | 任务组名称，建议包含随访类型和批次 |
| ScriptId | 糖尿病患者健康随访场景 ID |
| StrategyJson | 外呼策略 |
| CallingNumber | 主叫号码 |

建议任务组名称：

```text
糖尿病健康随访-YYYYMMDD-批次号
```

### 任务下发

创建任务组后，调用 `AssignJobs`，用 `JobGroupId` 下发具体患者外呼任务。

`JobsJson.extras` 至少需要包含本文第四节定义的变量。系统侧字段名必须和阿里云场景变量名保持一致。

示例结构：

```json
{
  "patient_name": "张女士",
  "manager_name": "李医生",
  "organization_name": "XX 慢病管理中心",
  "followup_reason": "本月糖尿病健康随访",
  "recent_glucose_summary": "近7天空腹血糖偏高，最高8.6mmol/L",
  "intervention_summary": "控制主食、每周运动3次、每日监测空腹血糖",
  "medication_summary": "二甲双胍每日2次",
  "control_goal_summary": "空腹血糖建议控制在4.4-7.0mmol/L",
  "last_followup_summary": "上次反馈晚餐主食偏多，运动不足"
}
```

## 八、回传系统后的处理

外呼结果进入我们系统后，生成一条“智能外呼随访记录”。

建议入库内容：

- 外呼任务组 ID：`JobGroupId`
- 外呼任务 ID
- 场景 ID：`ScriptId`
- 系统随访类型：`DIABETES_HEALTH_FOLLOWUP`
- 通话状态
- 通话时长
- 通话摘要
- 标签结果
- 关键原文
- 机器人执行人

PDCA 处理建议：

- P：由干预计划生成本次随访任务。
- D：通义晓蜜完成电话随访。
- C：根据血糖监测、依从性、风险信号检查干预执行效果。
- A：生成健管师待办、调整下次随访时间，必要时提示重新评估干预方案。

首期不要让外呼结果直接自动修改干预方案；只生成“调整建议”和“健管师待办”，由人工确认后进入新一轮计划。
