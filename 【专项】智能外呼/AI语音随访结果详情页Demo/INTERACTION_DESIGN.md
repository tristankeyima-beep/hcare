# AI 语音随访线索图交互设计

## 设计目标

让健管师按真实操作顺序完成四件事：先判断本次随访是否值得关注，再理解 AI 为什么得出结论，然后回看患者原话，最后展开并确认人工待办。

## 选定方案

采用 ECharts `graph` 系列构建“问题 → 患者回答 → AI 线索 → 管理动作”拓扑图，采用 GSAP 处理节点逐段出现、跨区域高亮和状态过渡。图表不替代正文；正文卡片、完整对话和待办继续承担可阅读、可操作、可审计的职责。

## 操作顺序

1. 用户进入页面，先阅读四项随访结果总览。
2. 点击“血糖情况”或“风险信号”总览卡，页面定位到线索图，并展开对应路径。
3. 在线索图中悬浮节点，查看时间、原话摘要、识别标签和 AI 置信度。
4. 点击问题节点展开患者回答；点击回答节点继续展开 AI 线索；点击线索节点联动高亮关注点和管理待办。
5. 点击图中“查看原话”或完整对话时间点，切换至完整对话页签并高亮对应消息。
6. 点击待办卡展开核验清单；再次点击可收起，演示人工确认前的工作准备状态。

## 图结构

```text
身份确认
  └─ 本人愿意接听
      ├─ 血糖监测问题
      │   └─ 空腹 7.4–8.1 / 餐后 12.6
      │       ├─ 餐后血糖偏高
      │       └─ 晚餐主食控制困难
      ├─ 风险症状问题
      │   └─ 手抖、出汗，进食后缓解，未测血糖
      │       └─ 疑似低血糖症状
      └─ 人工联系问题
          └─ 患者主动要求联系
              └─ 生成健管师待办
```

## 交互状态

- 默认：显示问题主干和“点击展开”提示。
- 悬浮：节点边框加深、连线增强，并展示 tooltip；相关正文卡片同步出现浅色高亮。
- 选中：右侧节点详情面板更新；相关子节点展开；当前路径之外的节点降低透明度。
- 全部展开：一次性展示完整线索链，用于演示讲解。
- 重置：回到只展示问题主干的初始状态。
- 播放路径：按真实对话先后自动逐层展开，动画结束后停留在健管师待办。
- 降级：ECharts 或 GSAP 未加载时，展示同样内容的可点击 HTML 路径，不影响理解。

## 页面联动

| 触发位置 | 联动结果 |
| --- | --- |
| 总览卡 | 定位线索图、展开对应路径、更新节点详情 |
| 图节点 Hover | 高亮相关关注点、资料或待办 |
| 图节点 Click | 展开子节点、更新详情面板 |
| “查看患者原话” | 切换到完整对话并定位消息 |
| 对话时间点 | 回到线索图并选中对应节点 |
| 待办卡 | 展开核验清单，显示人工处理边界 |

## 技术边界

- 页面仍为静态 Demo，不接真实患者数据、录音和任务接口。
- ECharts 与 GSAP 通过固定版本 CDN 引入；提供 HTML 降级结构。
- AI 线索只形成风险提示和待办，不直接更改患者方案。
- 动画遵循 `prefers-reduced-motion`，键盘用户可通过按钮和详情列表完成同样操作。
