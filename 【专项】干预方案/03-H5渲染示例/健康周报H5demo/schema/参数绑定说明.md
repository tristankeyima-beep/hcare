# 健康周报 H5 参数绑定说明

## 数据入口

H5 页面使用两类数据：

1. 页面外层元数据：患者姓名、周报生成时间，由小程序或业务后端额外传入，不由 Dify 生成。
2. 周报正文内容：Dify 健康周报最终出参 `finalPlanJsonText`。

```js
const pageMeta = {
  patientName: "王女士",
  reportGeneratedAt: "2026-06-12 16:30:00"
};
const finalPlanJsonText = outputs.finalPlanJsonText;
const planData = JSON.parse(finalPlanJsonText);
```

本 demo 同目录保留：

- `page-meta.json`：模拟外部传入的患者姓名和周报生成时间。
- `dify-final-plan.json`：模拟 Dify 返回的 `finalPlanJsonText`。

真实接入时，患者姓名和周报生成时间应由小程序或业务后端传给 H5；健康周报正文应以 Dify 返回的 `finalPlanJsonText` 为准。

当前 demo 也支持通过 URL 参数覆盖页面外层元数据：

```text
?patientName=王女士&reportGeneratedAt=2026-06-12%2016:30:00
```

## 页面绑定关系

| 页面区域 | 展示内容 | 数据来源 |
| --- | --- | --- |
| 顶部第一行 | 患者专属健康周报 | 外部传入 `pageMeta.patientName`，前端拼接为“{patientName}专属健康周报” |
| 顶部右侧 | 当前卡片页码 | 前端基于当前卡片序号和卡片总数计算 |
| 顶部第二行 | 周报生成时间 | 外部传入 `pageMeta.reportGeneratedAt` |
| 封面标题 | 周报标题 | `planData.planTitle` |
| 封面说明 | 本周总述 | `planData.planSummary` |
| 封面统计 | 健康主题数、周报条目数、本周重点数 | 基于 `planData.groups` 和 `groups[].items[]` 计算 |
| 主题卡片标题 | 每组第 1 条建议标题 | `groups[].items[0].title` |
| 主题卡片副标题 | 分组总结 | `groups[].groupSummary` |
| 主题卡片正文 | 建议正文 | `groups[].items[0].content` |
| 这周记录显示 | 分组依据 | `groups[].goalBasis` |
| 你可以这样理解 | 关注点 | `groups[].items[0].focusPoint` |
| 重要性标签 | 重要性 | `groups[].items[0].importance` |
| 下周关注卡 | 执行要点 | `planData.executionPoints` |

## Schema 文件

- `health-weekly-report.schema.json`：只描述 Dify 返回的 `finalPlan` 结构。
- `health-weekly-report-page.schema.json`：描述 H5 页面整体入参，包含外部传入的 `patientName`、`reportGeneratedAt` 和 Dify 返回的 `finalPlan`。

## 前端实现约束

- 健康内容不得在 H5 中硬编码，应来自 `finalPlanJsonText` 或本地 demo JSON。
- 患者姓名和周报生成时间不得写入或要求 Dify 生成，应作为 H5 页面外层参数传入。
- 页面可以保留固定 UI 文案，例如“左右滑动”“下一张”“这周记录显示”“你可以这样理解”。
- 如要展示趋势图、达标状态、评分、百分比，需要 Dify 出参新增结构化字段，前端不自行臆造。
- 当前 H5 默认每个 `group` 取 `items[0]` 作为一张主题卡。若后续每组有多条 item，需要决定是展开详情、组内列表，还是增加子卡片。
