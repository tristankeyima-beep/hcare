# 运动方案 H5 参数绑定说明

## 数据入口

H5 只接收 Dify 最终出参里的 `finalPlanJsonText`。

```ts
const planData = JSON.parse(finalPlanJsonText);
```

`finalPlanJsonText` 必须是一个 JSON 字符串，解析后需满足同目录下的：

```text
schema/sport-plan-final-json.schema.json
```

## 外部参数例外

页面允许额外传入姓名，用于封面展示“张三专属方案”。

```ts
const externalPatientInfo = {
  patientName: "张三"
};
```

除姓名外，页面上所有运动方案相关展示内容都必须来自 `finalPlanJsonText` 解析后的 `planData`。

## TypeScript 类型

```ts
type Importance = "重点执行" | "常规建议" | "补充建议";

interface SportPlan {
  planName: string;
  planTitle: string;
  planSummary: string;
  executionPoints: string;
  groups: AdviceGroup[];
}

interface AdviceGroup {
  groupTitle: string;
  groupType: "adviceList";
  groupSummary: string;
  displayStyle: string;
  dietPlanGoalLabel: string;
  goalBasis: string;
  items: AdviceItem[];
}

interface AdviceItem {
  itemType: "advice";
  day: number | "";
  title: string;
  content: string;
  focusPoint: string;
  importance: Importance;
  dailyTotalKcal: number | "";
  dailyTotalProteinG: number | "";
  dailyTotalFatG: number | "";
  estimatedEnergyDeficitKcal: number | "";
  meals: unknown[];
}
```

## 页面绑定关系

| H5 区域 | 绑定来源 | 说明 |
| --- | --- | --- |
| 顶部小标题 | `planData.planName` | 当前 demo 同时用于顶部状态和封面徽标。 |
| 封面主标题 | `planData.planTitle` | 不做额外改写。 |
| 封面姓名 | `externalPatientInfo.patientName` | 唯一外部参数，展示为“姓名 + 专属方案”。 |
| 封面摘要 | `planData.planSummary` | 原样展示。 |
| 封面待办卡标题 | 第一条 `importance === "重点执行"` 的 `item.title` | 若无重点条目，取第一条 `groups[].items[]`。 |
| 封面待办卡说明 | 同一条 item 的 `content` | 不拼接额外文案。 |
| 执行要点 | `planData.executionPoints` | 原样展示。 |
| 动作清单主题标题 | `groups[index].groupTitle` | 上方序号文案为 UI 固定标签：`主题 ${index + 1}`。 |
| 主题摘要 | `groups[index].groupSummary` | 为空时不展示摘要行。 |
| 动作标题 | `groups[index].items[itemIndex].title` | 原样展示。 |
| 动作正文 | `groups[index].items[itemIndex].content` | 原样展示。 |
| 关注点 | `groups[index].items[itemIndex].focusPoint` | 原样展示，前端固定标签为“关注点”。 |
| 重要性标签 | `groups[index].items[itemIndex].importance` | 值限定为 `重点执行`、`常规建议`、`补充建议`。 |

## 前端派生值

以下内容不是 Dify 文案，而是前端根据 `finalPlanJsonText` 派生的展示状态：

| 派生值 | 计算方式 |
| --- | --- |
| 方案分组数 | `planData.groups.length` |
| 执行动作数 | `planData.groups.flatMap(group => group.items).length` |
| 重点执行数 | `items.filter(item => item.importance === "重点执行").length` |
| 底部筛选 | 使用 `item.importance` 过滤：全部、重点执行、常规建议、补充建议。 |
| 空状态 | 当前筛选条件下没有任何可见 item 时展示。 |

## 静态 UI 文案

以下是 H5 控件或栏目文案，不属于业务方案内容：

- `执行要点`
- `运动动作清单`
- `全部`
- `重点`
- `常规`
- `补充`
- `关注点`
- `主题 ${index + 1}`
- `方案分组`
- `执行动作`
- `重点执行`
- `专属方案`

除姓名和这些栏目、按钮、标签文案外，业务展示内容应全部来自 `finalPlanJsonText`。

## 接入示例

```ts
function parseSportPlan(finalPlanJsonText: string): SportPlan {
  const data = JSON.parse(finalPlanJsonText);

  if (!data || typeof data !== "object") {
    throw new Error("finalPlanJsonText 不是合法对象");
  }

  if (!Array.isArray(data.groups) || data.groups.length === 0) {
    throw new Error("groups 不能为空");
  }

  return data as SportPlan;
}
```

## 渲染约束

- 不要从流式过程文案、Answer 分段或用户 query 中取业务展示内容。
- 不要在前端补写疾病、指标、运动目标、频次、阈值等业务文案。
- `title`、`content`、`focusPoint` 为空时应视为上游出参问题，不建议由前端生成替代医疗建议。
- `groupSummary` 可为空；为空时前端可以隐藏摘要区域。
- 统计和筛选可以由前端派生，但不能改变原始条目内容。
