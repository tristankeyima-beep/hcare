# 饮食方案 H5 参数绑定说明

## 数据入口

H5 页面只接收 Dify 最终出参里的 `finalPlanJsonText` 作为业务内容来源。

```js
const finalPlanJsonText = outputs.finalPlanJsonText;
const planData = JSON.parse(finalPlanJsonText);
```

`finalPlanJsonText` 本身是字符串，字符串内容必须是一个合法 JSON 对象。解析后的对象结构参考同目录下的 `intervention-plan.schema.json`。

## 外部参数例外

页面允许额外传入姓名，用于封面展示。

```js
const externalPatientInfo = {
  patientName: "张三"
};
```

除姓名外，页面上所有饮食方案相关展示内容都必须来自 `finalPlanJsonText` 解析后的 `planData`。

## 页面绑定关系

| 页面区域 | 展示内容 | 数据来源 |
| --- | --- | --- |
| 封面处方名称 | 方案类型名称 | `planData.planName` |
| 封面标题 | 方案标题 | `planData.planTitle` |
| 封面姓名 | 患者姓名专属方案 | `externalPatientInfo.patientName` |
| 封面主题 | 7 天菜谱分组标题 | `weeklyMealPlan.groupTitle` |
| 封面目标 | 饮食目标标签 | `weeklyMealPlan.dietPlanGoalLabel` |
| 封面统计 | 天数、日均千卡、日均缺口 | `weeklyMealPlan.items` 计算 |
| 执行要点 | 总体执行建议 | `planData.executionPoints` |
| 今日卡片 | 第 1 天标题、说明、重点、热量等 | `weeklyMealPlan.items[0]` |
| 建议列表 | 建议标题、内容、重点原因、重要级别 | `adviceList.groups[].items[]` |
| 7 天菜谱标签 | 天数、每日热量 | `weeklyMealPlan.items[].day`、`dailyTotalKcal` |
| 单日菜谱详情 | 当天标题、说明、重点、热量等 | `weeklyMealPlan.items[selectedDay]` |
| 餐次列表 | 餐次名、餐次热量、食物名称、重量、热量 | `weeklyMealPlan.items[].meals[]`、`foods[]` |

## 关键分组约定

`groups` 中必须至少包含两类分组：

| groupType | 用途 |
| --- | --- |
| `adviceList` | 饮食执行建议列表，可有多组 |
| `weeklyMealPlan` | 最近 7 天三餐菜谱，只应有一组 |

页面通过以下方式取数：

```js
const weeklyGroup = planData.groups.find((group) => group.groupType === "weeklyMealPlan");
const adviceGroups = planData.groups.filter((group) => group.groupType === "adviceList");
const weeklyItems = weeklyGroup.items;
```

## 前端实现约束

- 不要在 H5 中硬编码饮食建议、菜谱、营养数值、目标、执行要点。
- 可保留固定 UI 文案，例如按钮、栏目标题、单位、标签说明。
- 可基于 `finalPlanJsonText` 中的数组做前端计算，例如建议条数、7 天数量、日均千卡、日均热量缺口。
- 如 Dify 出参字段为空，前端可以做空态处理，但不应自行补写业务建议。
