# 代码节点出入参说明：格式化患者饮食管理画像

对应代码：`代码-格式化患者饮食管理画像.py`

## 这个节点做什么

放在“生成患者饮食管理画像”LLM 节点之后，对 LLM 出参做格式化和兜底，输出稳定字段给节点3/4/5使用。

支持两种输入方式：

- DIFY 已开启结构化输出：直接传入 `dietPlanGoal`、`patientContextPack` 等字段。
- DIFY 未开启结构化输出或模型返回在 `text` 中：传入 `text`，代码会尝试从中解析 JSON。

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `dietPlanGoal` | String | 否 | LLM 结构化输出的内部目标枚举。 |
| `dietPlanGoalLabel` | String | 否 | LLM 结构化输出的中文目标标签。 |
| `goalBasis` | String | 否 | LLM 结构化输出的目标依据。 |
| `patientContextPack` | Object / String(JSON) | 否 | LLM 结构化输出的患者饮食管理画像。 |
| `materialSummaryBundle` | Object / String(JSON) | 否 | LLM 结构化输出的三段摘要。 |
| `text` | String | 否 | 未开启结构化输出时，LLM 返回的整段 JSON 文本。 |
| `llmText` | String | 否 | `text` 的别名兜底。 |
| `llmOutput` | Object / String(JSON) | 否 | 上游 LLM 原始输出兜底。 |

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `dietPlanGoal` | String | 合法化后的内部目标枚举。仅供工作流内部使用。 |
| `dietPlanGoalLabel` | String | 中文目标标签。 |
| `goalBasis` | String | 目标依据。 |
| `patientContextPack` | String(JSON) | 格式化后的患者饮食管理画像，供后续 LLM 节点直接引用。 |
| `materialSummaryBundle` | String(JSON) | 格式化后的三段摘要，供后续 LLM 节点直接引用。 |
| `formattedProfileJson` | String(JSON) | 完整格式化画像，便于调试。 |
| `formatWarnings` | String(JSON Array) | 格式化过程中的兜底提醒。 |

## 兜底策略

- `dietPlanGoal` 非法时兜底为 `generalHealth`。
- `dietPlanGoalLabel` 缺失时按枚举自动补中文标签。
- `patientContextPack` 缺少某个维度时，补 1 条“暂无足够结构化证据”的安全占位。
- 每条画像 item 会保证包含 `evidence`、`impact`、`generationHint`。
- 输出给后续 LLM 的复杂对象统一为 JSON 字符串。
