# 代码节点出入参说明：格式化顶层总述字段

对应代码：`代码-格式化顶层总述字段.py`

## 这个节点做什么

放在“节点5-1：生成顶层总述字段”LLM 之后，把 LLM 输出的顶层文案字段解析、兜底并格式化为节点6可直接使用的 `planHeader`。

该节点只做结构格式化、默认文案兜底和简单口吻提醒，不重新生成业务内容。

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `planName` | String | 否 | DIFY 结构化输出字段。 |
| `planTitle` | String | 否 | DIFY 结构化输出字段。 |
| `planSummary` | String | 否 | DIFY 结构化输出字段。 |
| `executionPoints` | String | 否 | DIFY 结构化输出字段。 |
| `text` | String | 否 | 未开启结构化输出时，传入 LLM 的整段 JSON 文本。 |
| `llmText` | String | 否 | 兼容字段，作用同 `text`。 |
| `llmOutput` | Object/String | 否 | 兼容字段，可传 LLM 原始输出对象。 |

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `planName` | String | 格式化后的方案名称。 |
| `planTitle` | String | 格式化后的患者端标题。 |
| `planSummary` | String | 格式化后的方案摘要。 |
| `executionPoints` | String | 格式化后的执行要点。 |
| `planHeader` | String(JSON) | 节点6建议引用的顶层文案 JSON 字符串。 |
| `formattedPlanHeaderJson` | String(JSON) | 同 `planHeader`，便于调试或透传。 |
| `formatWarnings` | String(JSON Array) | 格式化和口吻提醒。为空数组字符串表示未发现结构问题。 |

## 节点6推荐接法

节点6的 `planHeader` 入参建议直接传：

```text
{{#节点5-2.planHeader#}}
```

不要优先把 `planName`、`planTitle`、`planSummary`、`executionPoints` 四个散字段分别接到节点6；散字段只作为兼容兜底使用。

## 兜底规则

- `planName` 为空时兜底为“饮食健康处方”。
- `planTitle` 为空时兜底为“个性化饮食管理建议”。
- `planSummary` 为空时使用面向患者的默认摘要。
- `executionPoints` 为空时使用默认执行原则和安全边界。

## 口吻提醒

如果 `planTitle`、`planSummary` 或 `executionPoints` 中出现“患者”“该患者”“结合患者情况”“制造热量缺口”等偏病历或内部表达，会写入 `formatWarnings`，方便在 DIFY 调试阶段发现文案问题。

最终顶层字段仍由节点6统一组装进标准 JSON。
