# 代码节点出入参说明：入参拆包与基础清洗

对应代码：`代码-入参拆包与基础清洗.py`

## 这个节点做什么

把 Start 节点传入的完整患者数据拆成节点2统一素材摘要 LLM 需要的 3 类上下文，并做基础兜底：

- 空对象/空数组兜底
- JSON 字符串解析
- 过长数组截断
- 统一带出 `planType`、`planGoalAndRequirements` 和 `extraSupplement`

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `planType` | String | 否 | 方案类型。运动方案工程期望为 `sport`，为空时默认 `sport`。 |
| `planGoalAndRequirements` | String | 否 | 本次运动方案目标和生成要求。 |
| `extraSupplement` | String | 否 | 健管师额外补充信息。 |
| `basicProfile` | Object 或 JSON字符串 | 否 | 基础档案。 |
| `diseaseProfile` | Object 或 JSON字符串 | 否 | 专病档案。 |
| `followupRecordsLast1y` | Array 或 JSON字符串 | 否 | 最近 1 年随访记录。 |
| `metricRecordsLast1y` | Array 或 JSON字符串 | 否 | 最近 1 年指标记录。 |
| `dietRecordsLast1y` | Array 或 JSON字符串 | 否 | 最近 1 年饮食记录，可辅助判断能量摄入和运动配合。 |
| `exerciseRecordsLast1y` | Array 或 JSON字符串 | 否 | 最近 1 年运动记录。 |
| `medPickupRecords1y` | Array 或 JSON字符串 | 否 | 最近 1 年取药记录。 |
| `activeControlGoals` | Array 或 JSON字符串 | 否 | 当前生效控制目标。 |

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `medicalGoalContext` | JSON String | 给节点2统一素材摘要 LLM 使用，用于提炼 `medicalGoalSummary`。 |
| `sportExecutionContext` | JSON String | 给节点2统一素材摘要 LLM 使用，用于提炼 `sportExecutionSummary`。 |
| `safetyBoundaryContext` | JSON String | 给节点2统一素材摘要 LLM 使用，用于提炼 `safetyBoundarySummary`。 |
| `planGoalAndRequirements` | String | 原样带出。 |
| `extraSupplement` | String | 原样带出。 |
| `planType` | String | 归一化后的方案类型。 |
| `routeWarning` | String | 当 `planType` 不是 `sport` 时提示调用方检查路由。 |
| `inputStats` | JSON String | 各类记录数量，便于排查入参是否为空。 |
