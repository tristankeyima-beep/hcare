# 代码节点出入参说明：入参拆包与基础清洗

对应代码：`代码-入参拆包与基础清洗.py`

## 这个节点做什么

把 Start 节点传入的完整患者数据拆成节点2“患者饮食管理画像”需要的 3 类上下文，并做基础兜底：

- 空对象/空数组兜底
- JSON 字符串解析
- 递归归一字段名：解析后的对象/数组如果仍包含下划线字段，会转换为驼峰字段
- 普通非空字符串保留为 `rawText`，避免 DIFY 测试或上游传参不是 JSON 时信息被静默丢弃
- 过长数组截断
- 统一带出 `planGoalAndRequirements` 和 `extraSupplement`

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `planType` | String | 否 | 方案类型。饮食方案工程期望为 `diet`，为空时默认 `diet`。 |
| `planGoalAndRequirements` | String | 否 | 本次饮食方案目标和生成要求。 |
| `extraSupplement` | String | 否 | 健管师额外补充信息。 |
| `basicProfile` | String(JSON) | 否 | 基础档案。当前 yml 从 Start paragraph 字段按字符串传入。 |
| `diseaseProfile` | String(JSON) | 否 | 专病档案。当前 yml 从 Start paragraph 字段按字符串传入。 |
| `followupRecordsLast1y` | String(JSON Array) | 否 | 最近 1 年随访记录。当前 yml 从 Start paragraph 字段按字符串传入。 |
| `metricRecordsLast1y` | String(JSON Array) | 否 | 最近 1 年指标记录。当前 yml 从 Start paragraph 字段按字符串传入。 |
| `dietRecordsLast1y` | String(JSON Array) | 否 | 最近 1 年饮食记录。当前 yml 从 Start paragraph 字段按字符串传入。 |
| `exerciseRecordsLast1y` | String(JSON Array) | 否 | 最近 1 年运动记录。当前 yml 从 Start paragraph 字段按字符串传入。 |
| `medPickupRecords1y` | String(JSON Array) | 否 | 最近 1 年取药记录。当前 yml 从 Start paragraph 字段按字符串传入。 |
| `activeControlGoals` | String(JSON Array) | 否 | 当前生效控制目标。当前 yml 从 Start paragraph 字段按字符串传入。 |

说明：

- 对象类入参如果传入合法 JSON 对象字符串，会解析为对象；如果传入普通字符串，例如 `"3"`，会输出为 `{"rawText":"3"}`。
- 数组类入参如果传入合法 JSON 数组字符串，会解析为数组；如果传入普通字符串，例如 `"7"`，会输出为 `[{"rawText":"7"}]`。
- 对象和数组内部字段会递归转换为驼峰。例如 `health_info.current_diseases` 会输出为 `healthInfo.currentDiseases`。
- 如果传入空字符串或空值，则仍按空对象 `{}` 或空数组 `[]` 兜底。

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `medicalGoalContext` | String(JSON) | 给节点2识别疾病边界、指标目标和饮食目的使用。内容是 JSON 字符串，便于 LLM 节点直接引用。 |
| `dietExecutionContext` | String(JSON) | 给节点2识别饮食行为、随访问题和执行障碍使用。内容是 JSON 字符串，便于 LLM 节点直接引用。 |
| `safetyEnergyContext` | String(JSON) | 给节点2识别用药安全、运动能量平衡和风险边界使用。内容是 JSON 字符串，便于 LLM 节点直接引用。 |
| `planGoalAndRequirements` | String | 原样带出。 |
| `extraSupplement` | String | 原样带出。 |
| `planType` | String | 归一化后的方案类型。 |
| `routeWarning` | String | 当 `planType` 不是 `diet` 时提示调用方检查路由。 |
| `inputStats` | String(JSON) | 各类记录数量，便于排查入参是否为空。内容是 JSON 字符串，便于 LLM 节点直接引用。 |

## 出参 JSON 字符串内容结构

```text
medicalGoalContext:
  planType
  basicProfile
  diseaseProfile
  metricRecordsLast1y
  activeControlGoals
  planGoalAndRequirements
  extraSupplement

dietExecutionContext:
  planType
  dietRecordsLast1y
  followupRecordsLast1y
  planGoalAndRequirements
  extraSupplement

safetyEnergyContext:
  planType
  medPickupRecords1y
  exerciseRecordsLast1y
  metricRecordsLast1y
  followupRecordsLast1y
  diseaseProfile
  planGoalAndRequirements
  extraSupplement
```
