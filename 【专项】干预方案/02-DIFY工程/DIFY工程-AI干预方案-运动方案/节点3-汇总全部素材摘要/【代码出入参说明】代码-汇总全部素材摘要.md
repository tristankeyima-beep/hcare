# 代码节点出入参说明：汇总全部素材摘要

对应代码：`代码-汇总全部素材摘要.py`

## 这个节点做什么

收集 3 个素材摘要 LLM 节点的输出，统一包装成 `material_summary_bundle`，供后续运动分组规划、items 生成和顶层总述生成节点使用。

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `medical_goal_summary` | Object 或 JSON字符串 | 否 | “疾病边界 + 指标目标摘要”节点输出。 |
| `sport_execution_summary` | Object 或 JSON字符串 | 否 | “运动能力 + 执行问题摘要”节点输出。 |
| `safety_boundary_summary` | Object 或 JSON字符串 | 否 | “安全风险 + 运动边界摘要”节点输出。 |
| `plan_goal_and_requirements` | String | 否 | 节点1原样带出的方案目标。 |
| `extra_supplement` | String | 否 | 节点1原样带出的补充信息。 |

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `material_summary_bundle` | Object | 三类摘要汇总结果。 |
| `summary_missing_fields` | Array<String> | 为空的摘要字段，便于排查某个并行节点失败。 |
| `plan_goal_and_requirements` | String | 原样带出。 |
| `extra_supplement` | String | 原样带出。 |

## 出参示例

```json
{
  "plan_goal_and_requirements": "生成控糖减重运动方案",
  "extra_supplement": "患者夜班较多",
  "material_summary_bundle": {
    "medical_goal_summary": "患者为2型糖尿病，需关注血糖、血压和体重...",
    "sport_execution_summary": "日常步数偏少，运动频率不足...",
    "safety_boundary_summary": "使用降糖药，运动前后需关注低血糖..."
  },
  "summary_missing_fields": []
}
```
