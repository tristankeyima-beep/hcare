# 代码节点出入参说明：入参拆包与基础清洗

对应代码：`代码-入参拆包与基础清洗.py`

## 这个节点做什么

把 Start 节点传入的完整患者数据拆成 3 类下游摘要节点需要的上下文，并做基础兜底：

- 空对象/空数组兜底
- JSON 字符串解析
- 过长数组截断
- 统一带出 `plan_type`、`plan_goal_and_requirements` 和 `extra_supplement`

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `plan_type` | String | 否 | 方案类型。运动方案工程期望为 `sport`，为空时默认 `sport`。 |
| `plan_goal_and_requirements` | String | 否 | 本次运动方案目标和生成要求。 |
| `extra_supplement` | String | 否 | 健管师额外补充信息。 |
| `basic_profile` | Object 或 JSON字符串 | 否 | 基础档案。 |
| `disease_profile` | Object 或 JSON字符串 | 否 | 专病档案。 |
| `followup_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年随访记录。 |
| `metric_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年指标记录。 |
| `diet_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年饮食记录，可辅助判断能量摄入和运动配合。 |
| `exercise_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年运动记录。 |
| `med_pickup_records_1y` | Array 或 JSON字符串 | 否 | 最近 1 年取药记录。 |
| `active_control_goals` | Array 或 JSON字符串 | 否 | 当前生效控制目标。 |

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `medical_goal_context` | Object | 给“疾病边界 + 指标目标摘要”节点使用。 |
| `sport_execution_context` | Object | 给“运动能力 + 执行问题摘要”节点使用。 |
| `safety_boundary_context` | Object | 给“安全风险 + 运动边界摘要”节点使用。 |
| `plan_goal_and_requirements` | String | 原样带出。 |
| `extra_supplement` | String | 原样带出。 |
| `plan_type` | String | 归一化后的方案类型。 |
| `route_warning` | String | 当 `plan_type` 不是 `sport` 时提示调用方检查路由。 |
| `input_stats` | Object | 各类记录数量，便于排查入参是否为空。 |
