# 代码节点出入参说明：入参拆包与基础清洗

对应代码：`代码-入参拆包与基础清洗.py`

## 这个节点做什么

把 Start 节点传入的完整患者数据拆成节点2“患者饮食管理画像”需要的 3 类上下文，并做基础兜底：

- 空对象/空数组兜底
- JSON 字符串解析
- 普通非空字符串保留为 `raw_text`，避免 DIFY 测试或上游传参不是 JSON 时信息被静默丢弃
- 过长数组截断
- 统一带出 `plan_goal_and_requirements` 和 `extra_supplement`

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `plan_type` | String | 否 | 方案类型。饮食方案工程期望为 `diet`，为空时默认 `diet`。 |
| `plan_goal_and_requirements` | String | 否 | 本次饮食方案目标和生成要求。 |
| `extra_supplement` | String | 否 | 健管师额外补充信息。 |
| `basic_profile` | Object 或 JSON字符串 | 否 | 基础档案。 |
| `disease_profile` | Object 或 JSON字符串 | 否 | 专病档案。 |
| `followup_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年随访记录。 |
| `metric_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年指标记录。 |
| `diet_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年饮食记录。 |
| `exercise_records_last_1y` | Array 或 JSON字符串 | 否 | 最近 1 年运动记录。 |
| `med_pickup_records_1y` | Array 或 JSON字符串 | 否 | 最近 1 年取药记录。 |
| `active_control_goals` | Array 或 JSON字符串 | 否 | 当前生效控制目标。 |

说明：

- 对象类入参如果传入合法 JSON 对象字符串，会解析为对象；如果传入普通字符串，例如 `"3"`，会输出为 `{"raw_text":"3"}`。
- 数组类入参如果传入合法 JSON 数组字符串，会解析为数组；如果传入普通字符串，例如 `"7"`，会输出为 `[{"raw_text":"7"}]`。
- 如果传入空字符串或空值，则仍按空对象 `{}` 或空数组 `[]` 兜底。

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `medical_goal_context` | String(JSON) | 给节点2识别疾病边界、指标目标和饮食目的使用。内容是 JSON 字符串，便于 LLM 节点直接引用。 |
| `diet_execution_context` | String(JSON) | 给节点2识别饮食行为、随访问题和执行障碍使用。内容是 JSON 字符串，便于 LLM 节点直接引用。 |
| `safety_energy_context` | String(JSON) | 给节点2识别用药安全、运动能量平衡和风险边界使用。内容是 JSON 字符串，便于 LLM 节点直接引用。 |
| `plan_goal_and_requirements` | String | 原样带出。 |
| `extra_supplement` | String | 原样带出。 |
| `plan_type` | String | 归一化后的方案类型。 |
| `route_warning` | String | 当 `plan_type` 不是 `diet` 时提示调用方检查路由。 |
| `input_stats` | String(JSON) | 各类记录数量，便于排查入参是否为空。内容是 JSON 字符串，便于 LLM 节点直接引用。 |

## 出参 JSON 字符串内容结构

```text
medical_goal_context:
  plan_type
  basic_profile
  disease_profile
  metric_records_last_1y
  active_control_goals
  plan_goal_and_requirements
  extra_supplement

diet_execution_context:
  plan_type
  diet_records_last_1y
  followup_records_last_1y
  plan_goal_and_requirements
  extra_supplement

safety_energy_context:
  plan_type
  med_pickup_records_1y
  exercise_records_last_1y
  metric_records_last_1y
  followup_records_last_1y
  disease_profile
  plan_goal_and_requirements
  extra_supplement
```
